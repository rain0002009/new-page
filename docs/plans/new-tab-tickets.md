# 新标签页工作台任务拆分草稿

来源：GitHub 规格 Issue #1（rain0002009/new-page）。读取了完整正文与评论，目前没有评论或其他任务。

状态：等待用户确认粒度、阻塞关系与是否合并或继续拆分。T01–T14 是草稿编号，不是 GitHub Issue 编号，尚未发布。

## 拆分原则

- 每项交付一个可从新标签页操作并验收的完整行为，包含所需数据变化、扩展后台连接、界面和行为测试。
- 当前只有官方模板，不单开重构或安装样式库任务。T01 将替换模板、UnoCSS 与 tailwind-variants 接入、本地持久化和首条真实用户流程一起交付。
- 前面的本地功能是可验证的增量，首版完成后首次无数据必须走 WebDAV 配置，不能用开发阶段入口取代最终配置体验。
- 每项从首次落地就遵循柔和亮色、键盘可操作、图标可辨识及适配窄窗口要求；不把视觉和可访问性集中推迟到末尾。
- UI 行为通过已确认的新标签页最高层测试边界验收。远端相关任务使用受控 HTTPS WebDAV 和独立浏览器配置；不能用用户真实凭据与收藏作测试数据。
- 阻塞边只列直接前置，隐含继承前置任务的依赖。并行分支并不意味着每张任务都必须等待 WebDAV：本地功能可先独立验收，接入后复用同一持久化与变更边界。
- 发布时每项正文引用规格 #1，使用 ready-for-agent 标签并建立任务之间的阻塞关系。不修改或关闭规格 Issue，也不修改它的子任务关系。

## T01：新标签页创建并持久保存第一条收藏

## Parent

rain0002009/new-page#1

## What to build

用户能够在柔和亮色三栏新标签页中，向默认空间的默认收藏块手动添加真实链接，看到标题、图标和备注，并打开网页；关闭页面或浏览器再打开后，已添加内容仍然存在。该最小本地工作流承载样式接入、统一业务操作与持久化边界，供后续切片复用。

## Acceptance criteria

- [ ] 使用 React、TypeScript、pnpm、UnoCSS、tailwind-variants，替换欢迎页为奶白、浅灰、鼠尾草绿的三栏布局。
- [ ] 新建空数据时创建“我的空间”和一个空收藏块；左侧有昵称、空间及 Todo、搜索、设置导航位置，后续功能未交付时不伪装已可使用。
- [ ] 手动添加 HTTP/HTTPS 链接，保存独立身份、网址、标题、图标和备注；相同网址允许重复。
- [ ] 卡片展示元信息，图标缺失时显示占位；点击卡片在新标签页打开网页。
- [ ] 每次创建先自动持久保存本地，重开页面及浏览器后结果仍然存在；没有单独保存按钮。
- [ ] 通过统一业务操作更新工作副本，已完成操作与未上传状态不只存在于 React 或 Query 内存缓存。持久化模型能承载稳定条目身份与后续同步版本。
- [ ] 从真实新标签页完成添加、打开、重开及重复网址独立性验收；窄窗口内容可用、主要操作可经键盘触发。
- [ ] Chrome 生产构建与 TypeScript 类型检查通过。本地增量演示入口不替代 T02 的最终首次配置体验。

## Blocked by

None (can start immediately).

## T02：配置 WebDAV 并完成单数据源自动同步

## Parent

rain0002009/new-page#1

## What to build

用户首次配置昵称及 HTTPS WebDAV 后，能读取已有远端收藏或初始化空数据。新增内容自动保存本地并上传，打开新标签页先显示本地内容再后台刷新；断网和认证失效期间继续使用，恢复后自动重试，并可在设置中查看状态和手动同步。

## Acceptance criteria

- [ ] 首次没有数据时展示配置页，可填写昵称、地址、用户名及密码或应用专用密码；连接成功后进入工作台。
- [ ] 读取已有远端数据，不被默认空空间覆盖；只有确认远端为空时初始化。认证、格式或能力错误不能解释为空数据。
- [ ] 验证远端必要读写及安全条件更新能力，扩展后台在用户授权的服务器范围内完成网络请求；权限拒绝、撤销与能力不足有可理解提示。
- [ ] 修改本地先持久化并自动上传；远端拉取、失败或重试不覆盖未上传修改，多个同源新标签页的操作不相互丢失。
- [ ] 单数据源下重开优先显示本地，后台刷新；离线、认证失效和后台重启后待上传内容保留，恢复连接可自动重试。
- [ ] 设置提供昵称修改、同步中、待同步、失败状态和手动同步；昵称属于远端业务数据，凭据仅当前设备保存，不进入远端内容或日志。
- [ ] 从首次接入即按服务器和账号绑定本地状态。本任务尚未支持用户切换和迁移操作，但不得混用不同源的数据；完整界面由 T14 交付。
- [ ] 并发发现远端版本改变时保留本地和远端数据并安全暂停相关写入；不在 T11、T12 交付前用整文件强制覆盖代替合并。
- [ ] 用受控 HTTPS WebDAV 验收空远端、已有远端、延迟、离线、认证失败、权限拒绝和版本变动；验证远端实际内容及重开恢复结果。

## Blocked by

## T03：管理与排序空间和收藏块

## Parent

rain0002009/new-page#1

## What to build

用户可以创建、重命名和拖拽排序空间与收藏块，切换空间查看自己的分组，折叠不常用的内容。打开新标签页默认进入空间顺序中的第一个空间。

## Acceptance criteria

- [ ] 空间支持创建、改名、切换和实际拖拽排序，重复打开时默认显示第一个空间。
- [ ] 收藏块支持创建、改名、折叠、展开及空间内实际拖拽排序。
- [ ] 手动新增收藏位于用户选中的空间和收藏块中；各空间内容不会串入其他空间。
- [ ] 所属关系、名称和顺序自动持久化，重开后保持；不靠网址判断对象身份。
- [ ] 新增业务内容沿用统一操作与工作副本模型，接入 T02 后可随应用数据一起往返，不另建不受同步管理的 UI 数据。
- [ ] 通过浏览器实际操作验收多空间、多收藏块、折叠与排序；删除及恢复整体由 T09 交付。

## Blocked by

- T01：新标签页创建并持久保存第一条收藏。

## T04：实时待选标签页与拖入即收藏

## Parent

rain0002009/new-page#1

## What to build

右侧实时展示新标签页所属 Chrome 窗口里的普通网页。用户把其中一个条目拖入收藏块，就直接得到一张完整的收藏卡片，不弹窗、不补充信息，原网页继续打开。

## Acceptance criteria

- [ ] 仅查询本新标签页所属窗口，条目展示可用标题、网址和图标，缺失图标有占位。
- [ ] 打开、关闭、加载完成、标题变化、顺序变化及跨窗口移入移出后列表更新；另一个窗口获得焦点不改变所属窗口范围。
- [ ] 只允许 HTTP/HTTPS 页面，过滤浏览器内部页面、扩展页面与新标签页。
- [ ] 真实拖拽条目到默认或其他已存在收藏块，直接复制标题、网址和图标创建收藏，备注初始为空；不弹窗或要求保存确认。
- [ ] 原标签页保留，拖入重复网址创建独立条目，重新打开新标签页后收藏仍在。
- [ ] 宽窗口右侧可用；窄窗口从抽屉仍能选择并拖入。没有网页和标签页权限不可用时有明确状态。
- [ ] 用可控网页和真实浏览器标签页事件验收列表、过滤、拖入与持久化，不仅调用内部创建函数代替拖拽。

## T05：弹窗编辑收藏并自动保存

## Parent

## What to build

用户悬浮收藏卡片后可进入编辑弹窗，修改网址、标题和备注，改动自动保存。编辑某个重复网址条目只影响该条收藏。

## Acceptance criteria

- [ ] 悬浮与键盘操作可进入编辑，图标按钮有可辨识名称，不触发卡片导航。
- [ ] 弹窗显示当前网址、标题和备注，可修改并自动保存有效内容；没有独立保存按钮。
- [ ] 无效网址有明确提示，不把已有有效收藏覆盖为无效数据。
- [ ] 关闭弹窗、重开页面或浏览器后有效修改保留；快速关闭不丢失已完成的有效修改。
- [ ] 重复网址条目有各自身份，编辑一个不会更改另一个；网页图标缺失或加载失败不影响编辑和打开。
- [ ] 从真实新标签页完成编辑、非法输入、关闭与恢复验收，沿用现有行为测试边界。

## T06：拖拽排序收藏并在同空间跨块移动

## What to build

用户拖拽已收藏卡片改变位置，或把它移到同空间内另一收藏块；空块和折叠块都能作为目标，跨空间移动被阻止。

## Acceptance criteria

- [ ] 空收藏块可接收卡片；折叠块可接收，添加后展开。
- [ ] 跨空间目标不接受移动，无效落点或取消拖拽不会丢失、复制或改变原卡片。
- [ ] 移动及排序结果自动保存，重开后仍保持；相同网址的条目不会被合并。
- [ ] 浏览器输入驱动验收顺序与落点，不用直接调用内部移动函数代替交互；现有编辑、打开和拖入流程保持可用。

## T08：书签开关与全局 Todo

## Parent

rain0002009/new-page#1

## What to build

用户在收藏卡片上点亮书签，链接就进入全局 Todo；完成后它从 Todo 消失，原收藏保留并熄灭。需要再次处理时回到收藏处重新点亮。

## Acceptance criteria

- [ ] 每张收藏卡片有独立书签开关，卡片上可识别是否点亮。
- [ ] Todo 页只汇集全部空间中点亮的有效收藏；切换功能页时保留左右区域。
- [ ] 点击完成只清除该条收藏的标记，立即从 Todo 消失，原卡片仍在且书签熄灭。
- [ ] 回到原收藏可再次点亮加入；不提供手动普通任务、完成列表或独立任务副本。
- [ ] 同网址的两个条目独立切换状态；状态自动持久化并在重开后恢复。
- [ ] 通过新标签页实际执行加入、完成、重开、再次加入及重复条目独立性验收；多空间场景在具备 T03 的集成中验证，不因此增加本任务的前置依赖。

## Blocked by

- T01：新标签页创建并持久保存第一条收藏。

## T09：删除收藏内容与 30 天回收站恢复

## Parent

rain0002009/new-page#1

## What to build

用户可以删除链接、收藏块或空间，并从设置中的回收站恢复；子内容与待办标记一起保留 30 天。误删可恢复，已删除内容不会继续出现在有效收藏和 Todo 中。

## Acceptance criteria

- [ ] 卡片悬浮提供删除入口；链接、收藏块和空间删除后进入回收站。
- [ ] 删除空间展示内容数量并确认，不能删除最后一个空间；取消不改变数据。
- [ ] 父级删除时子内容一起离开有效区域，相关 Todo 即时移除；保留身份、归属和原待办标记。
- [ ] 从回收站恢复后层次有效，恢复原待办标记；原父级未恢复时不产生孤立链接。
- [ ] 删除、恢复与保留期信息持久化；30 天后按策略清理，但保留必要的删除事实供同步防止旧内容复活。
- [ ] 重开后回收站与恢复结果仍一致；接入远端后删除和回收站与其他业务内容同样参与同步。
- [ ] 浏览器流程覆盖单条与整体删除、取消、最后空间保护和带待办恢复；受控时钟覆盖到期，不真实等待 30 天。

## Blocked by

- T03：管理与排序空间和收藏块。
- T08：书签开关与全局 Todo。

## T10：全空间搜索、操作与定位收藏

## What to build

用户搜索所有空间中的标题、网址和备注，结果显示归属，并可直接打开、编辑、删除或定位原收藏块。

## Acceptance criteria

- [ ] 搜索覆盖所有空间有效收藏的标题、网址和备注，相同网址条目独立出现。
- [ ] 结果标明空间和收藏块，定位操作切换到原位置，原块折叠时使结果可见。
- [ ] 从结果打开、编辑、删除或切换待办，行为与原收藏一致，结果随改动更新。
- [ ] 回收站内容不参与有效收藏搜索，恢复后重新可检索。
- [ ] 搜索仅替换中间内容区，左右导航与待选区域保持；加载与空结果状态清晰。
- [ ] 从真实新标签页验证跨空间匹配、备注修改、删除与恢复后的结果，以及定位和打开行为。

## T11：两设备自动合并不同条目的修改

## Parent

rain0002009/new-page#1

## What to build

两个设备可以离线修改不同的收藏内容，恢复联网后自动合并并显示一致结果。重试、重复刷新和后台重启不重复新增，也不覆盖任一设备尚未上传的修改。

## Acceptance criteria

- [ ] 使用两个隔离浏览器配置连接同一测试数据源，通过真实界面分别创建或修改不同收藏、空间或收藏块。
- [ ] 两端先显示各自本地数据，恢复连接后合并不同条目的修改，无需用户逐项手动确认。
- [ ] 已读远端版本与本地未上传操作参与合并，上传使用已验证的安全并发控制；服务端版本变动时重新读取，不强制覆盖。
- [ ] 网络抖动、重复重试、重开页面或后台重启后同一操作不会重复应用或丢失。
- [ ] 同一内容冲突仍保留双方并提示尚待处理，不能通过时间较新就丢弃另一版；交互选择由 T12 完成。
- [ ] 同步状态真实反映待同步与失败；不同条目成功合并后两设备界面和远端业务内容一致。

## T12：同一内容冲突选择与删除、排序一致性

## Parent

## What to build

两设备修改同一内容时，用户能看到两个版本并选择处理结果；删除与编辑、拖拽与排序同时发生时，不会静默丢失内容或破坏空间、收藏块、Todo 和回收站的一致性。

## Acceptance criteria

- [ ] 相同内容产生冲突时保存双方版本，设置或同步提示能进入可理解的选择界面。
- [ ] 用户未选择前双方内容均可恢复；重开后冲突仍在，不伪报所有内容已完成同步。
- [ ] 选择后的结果持久化并同步至双方，重复刷新不再次制造已解决的同一冲突。
- [ ] 并发删除与编辑、恢复、块内排序及跨块移动均保持有效身份与父子关系，不能产生孤立条目或静默丢失一端修改。
- [ ] 删除事实传播后，旧设备或离线设备重连不能使已删除和到期清理的内容复活；与真实编辑冲突时保留可选择版本。
- [ ] 所有业务内容，包括昵称、顺序、待办与回收站，通过同一同步约定保持一致；一次失败不能丢失待上传工作。
- [ ] 用两浏览器和受控 WebDAV 从界面制造冲突并解决，验证真实远端及重开结果，覆盖远端条件写入拒绝、重复重试和回收站到期后的重连。

## T13：无凭据备份导出与校验恢复

## Parent

## What to build

用户从设置导出可恢复的业务备份，并能导入合法备份恢复内容；密码不外泄，错误文件和不兼容格式不会破坏当前收藏。

## Acceptance criteria

- [ ] 导出包含格式版本、昵称、空间、收藏块、链接、顺序、待办与回收站等业务内容。

- [ ] 恢复只作用于用户确认的当前数据源，沿用本地持久化和自动同步边界，不绕过待上传保护。
- [ ] 从设置执行真实导出与导入，验证合法往返、损坏文件、不兼容版本、非空目标保护和无凭据内容。

## T14：隔离切换 WebDAV 与确认合并迁移

## Parent

rain0002009/new-page#1

## What to build

用户更换 WebDAV 时，明确选择切换到另一份数据或迁移当前数据。每个数据源的缓存与待上传内容隔离，迁移先读取目标并在目标非空时确认合并。

## Acceptance criteria

- [ ] 设置明确区分切换数据源与迁移当前数据两种操作。
- [ ] 切换后读取新源业务数据或已存在的新源缓存，不自动把旧源内容和待上传操作传给新源。
- [ ] 切回旧源仍能恢复其缓存与未上传内容，网络请求、同步进度和凭据不串源。
- [ ] 迁移前验证目标并读取已有数据；目标非空时展示确认合并，取消不改变目标。
- [ ] 确认后的合并复用已有冲突保护，重复网址允许保留，不以网址去重；双方内容不被静默整份覆盖。
- [ ] 迁移失败或认证被拒绝时源数据和待上传修改完整保留，可重试，不误报成功。
- [ ] 通过两个隔离 WebDAV 数据源验收切换、离线切回、非空迁移、取消、冲突处理和失败恢复，核对实际远端内容。
