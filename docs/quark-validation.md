# 夸克直连实现与验证

日期：2026-11-10。实现基于 `bcd27a6`，调整后的存储决策见 ADR 0002。

## 行为

新安装默认使用夸克扫码。登录获取、Cookie 轮换、目录列表、分片上传与下载均由扩展后台直接访问夸克/上传服务，不需要自建 Worker。已存储的 WebDAV 账号和本地收藏继续可用，并提供扫码迁移入口。

所有操作先持久化本地。云端每次保存生成独立版本文件，内容散列作为版本标识，文件名携带父版本引用，上传后按 fid 下载校验；不删除正在使用的旧文件。并行保存保留所有分支，按共同祖先合并，并继续使用现有冲突处理。已确认上传的版本尚未出现在目录中时暂停刷新，不把旧列表当作最新内容回退本地数据。云端历史暂不自动清理，设置页说明历史文件与当前回收站清理期限的区别。

浏览器 Cookie 通过本扩展请求的 `webRequest` 响应事件捕获；每个请求使用仅匹配本扩展与具体 URL 的临时 DNR 请求头规则。只允许受支持的 HTTPS 夸克/上传域名，逐跳处理登录 Cookie；不会把登录 Cookie 传进 OSS 分片上传。Cookie 只保存在扩展本地认证存储，不出现在界面消息、业务文件或导出备份。

## 验证边界

使用真实 Chrome、扩展后台及受控 HTTPS Quark API，接口夹具要求真实扫码 Cookie 往返、Cookie 轮换、登录 302 跳转，检查上传内容 MD5/SHA-1、multipart 提交 Content-MD5 和签名相关请求头，再验证下载内容。测试替换的是复制到隔离浏览器配置中的构建地址；源代码和交付构建保留真实夸克地址。

回归包括扫码后首次保存与跨设备读取、上传失败保留旧文件与本地编辑、二维码过期、登录失效后重新扫码、账号隔离、并行收藏合并、同条目版本选择、损坏数据保护、目录可见性延迟、扫码成功后读取失败重试、WebDAV 收藏及待办迁移。原有收藏、拖放、Todo、搜索、回收站、备份与 WebDAV 浏览器回归继续执行。

目录延迟回归先在未加已知版本保护的构建上失败：隐藏刚上传的版本后，界面错误报告“已同步”，会采纳旧版本。修复后显示“新版本尚未出现在目录列表”，保留本地收藏，列表恢复后正常同步。扫码成功后读取失败也提供重试入口，不需要重复扫码。

另用独立临时 Chrome 配置访问真实夸克匿名二维码接口，确认生产请求适配能够渲染二维码。没有登录任何真实账号，没有访问或上传用户网盘文件；真实账号确认后的登录与上传仍待安装验收。该临时配置和诊断脚本在检查后清理。

## 验证结果

`pnpm typecheck`、`pnpm build:chrome` 通过。新增目录延迟、扫码读取失败重试与 GET/PUT 缺失 ETag 的四条针对性回归通过。最终完整浏览器回归 `pnpm test:e2e` 共 31 条全部通过，耗时 4.5 分钟。
