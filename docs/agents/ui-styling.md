# UI 样式

## 选择写法

- 布局、间距、字号、颜色、响应式及交互状态优先写 UnoCSS 工具类，放在所属 JSX 附近。
- 同一 module 有重复使用的尺寸、外观或状态组合时，用 `tailwind-variants/lite` 的 `tv()` 集中管理；多个关联节点用 slots。tv 的 implementation 应直接包含工具类。
- 共享视觉值放在 `uno.config.ts` 的 theme；一次性值可用任意值工具类。保留已有断点和像素尺寸，迁移时核对实际生成的 CSS。
- 只有浏览器全局重置、第三方 DOM / 主题适配、必要关键帧，或已确认工具类无法表达的规则才保留手写 CSS。在规则旁说明用途。第三方原生样式使用其包导入。
- 运行时测量得到的拖拽尺寸、位置及动画可用 style 或动画接口；静态外观仍使用工具类。

## 修改现有 UI

1. 先检查共享 UI module 与所有相关选择器，包括父级覆盖、媒体查询和后追加的同名规则，确认最终生效的外观。
2. 优先复用现有 Button、Modal、SiteIcon 的 interface。一次性定制放在调用处；只有实际复用的变化才扩展 variants。
3. lite 不自动合并冲突工具类。每个状态下每项属性只保留一个来源；需要完全定制某个 Button 变体时传 `tone="custom"` 或 `size="custom"`，在调用处完整提供该部分样式。className 用于补充独立属性，避免靠拼接顺序覆盖默认值。
4. 工具类必须是完整静态字符串；动态状态用 variants、完整类名分支或 data / aria 变体表达，让 UnoCSS 能扫描到。
5. 同一属性跨多个任意媒体查询变化时，优先使用互不重叠的区间；UnoCSS 会重排查询，核对生成顺序及断点前后的实际布局。隐藏侧栏或抽屉时，确认内容区同时释放对应宽度。
6. 迁移一项即删除对应 CSS 及历史覆盖。尚未迁移的页面规则可留在原处；本次触及的样式按上述写法实现，修复时回到规则所属位置。

## 完成检查

- 对照 diff：新增外观由工具类或 tv 实现；保留的手写 CSS 符合例外并有说明；已迁移部分不再依赖全局业务选择器。
- 图标、测试或拖拽仍使用的类名可作为 DOM 标识保留，核对引用后再删除。
- 运行项目类型检查与对应扩展构建，核对任意值、伪元素和响应式类生成的实际声明。
- 复用与改动相关的界面测试，检查桌面、窄窗口、hover、键盘焦点、disabled，以及受影响的弹窗或拖拽。测试可见行为与布局约束，不锁定工具类字符串。
