# Domain docs

This repository uses a single-context layout:
CONTEXT.md at the root and decisions under docs/adr/.

Before exploring code, read CONTEXT.md and ADRs relevant to the work.
If these files are absent, proceed silently. Create them lazily when
domain-modeling resolves terminology or decisions.

Use the vocabulary defined in CONTEXT.md when naming domain concepts.
Flag conflicts with existing ADRs explicitly, naming the decision.
