# 夸克可读文件与有限历史验证

关联 GitHub Issue #21，决策见 ADR 0005。范围为 Chrome Manifest V3，新格式直接启用，不提供旧版夸克快照迁移。用户负责清空旧云端测试文件及扩展本地测试数据，重新扫码连接。

## 文件与同步

- 所有业务文件都在夸克根目录的「拾页收藏」文件夹内。其下为 `收藏.json`、`笔记/` 和 `同步历史/`，不会将业务文件放在网盘根目录。
- `收藏.json` 保留完整当前数据，并列出笔记文件路径；有效笔记发布为原始 Markdown 字节，同名笔记有不同的稳定后缀，更名、删除和父级恢复会更新文件。云端 Markdown 是扩展发布的副本，手工修改不回写。
- 提交内含版本向量、完整数据与合并基线，下载后校验内容散列。成功合并和发布后保留当前提交及最近 10 个已合并旧提交，冲突分支在选择前不清理。
- 发布时校验临时文件，暂存原文件后更名，避免依赖网盘允许覆盖同名文件。发布与清理失败均保留同步错误并在下次同步修复；相同内容的临时文件可复用，不因修复发布而新增业务版本。
- 单次提交含当前数据和合并基线，总上传限制 10 MB，并受夸克分片上限约束。

## 验证方式

沿用项目的真实隔离 Chrome 扩展与受控 HTTPS 夸克服务。服务检查 Cookie 轮换、上传 MD5/SHA-1、OSS 签名、multipart 提交及实际文件字节；新增真实目录、重命名和删除操作，重命名拒绝覆盖同名文件，并支持发布、清理失败注入。没有访问用户真实夸克账号。

首轮 8 项相关流程全部通过（4.0 分钟），随后加强文件替换与重试清理，并按用户要求移除旧版夸克迁移。最终回归记录如下。

- 类型检查：`node node_modules/typescript/bin/tsc --noEmit` 通过。
- Chrome 构建：`node node_modules/extension/bin/extension.cjs build --browser chrome` 通过，Node 22.23.1 / Extension.js 4.1.39。文档页仍有既有 1.28 MiB 超过 1 MiB 建议预算的警告。
- 18 项相关回归：16 项通过（9.1 分钟）；笔记备份用例在最后的恢复搜索步骤超出 45 秒总时限，并发合并用例暴露等价合并反复产生分支的问题。已将备份完整流程时限设为 90 秒，并修复合并去重和文件发布竞争重试；对这两项及冲突选择、失败恢复进行重复复测，结果见下。

未对真实账号进行扫码确认、上传、更名或删除验收；受控接口通过不能替代真实夸克服务验收。

## 并发与恢复补充

多设备同时合并完全相同的分支及结果时使用由分支和结果派生的合并标识，使提交内容一致，避免等价合并反复形成新分支。文件发布遇到另一设备抢先更名或清理造成的 404/409 时重试；远端版本变化时先重新合并，服务不可用与真实上传失败继续显示错误并保留本地数据。
