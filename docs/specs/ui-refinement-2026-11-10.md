# 精简收藏与 Todo 交互，并接入 fluid-prism 浅色流体视觉

2026-11-12 待选区域增量：新增[一键收藏、单条关闭与排序规格](tab-inbox-actions-2026-11-12.md)，替代下文“移除批量入口”和“日常新增只支持拖入”的限制。一键收藏无需命名弹窗，保存成功后关闭原页；手动新增入口仍不提供。

2026-11-12 增量状态：本轮拖拽收集已整理为独立的[拖拽收集规格](drag-collection-2026-11-12.md)。新规格取代原标签页保留及待选预览保持原样式的要求；不表示本轮功能已经实现。

## Problem Statement

现有新标签页工作台已经提供空间、收藏块、收藏链接、待选区域、Todo、本地保存与同步，但页面的交互和视觉与用户实际使用习惯存在偏差。手动添加链接和批量收藏形成多余入口；部分对象需要寻找专用图标才能拖动；空备注被提示文案填满。大量口号、问候和重复保存说明占用注意力。

Todo 直接复用链接卡片，呈现密度和操作数量不适合逐项处理待办，且不能独立上下排序。用户希望 Todo 成为清晰的纵向清单，同时保留标题打开网页和稳定的三栏结构。整体页面需要在当前浅色主调上明显增强流体与光泽效果。

## Solution

将日常新增收藏统一为从右侧待选区域拖入已有收藏块，或在已有收藏块边缘触发快捷建块落点后松手收集。所有可拖拽对象使用整体拖动，空备注直接留空，页面只展示必要的操作与状态信息。

Todo 使用纵向列表，每行仅提供标题打开网页、完成和整行上下拖拽。待办顺序独立于收藏顺序，自动保存并参与现有同步；新加入和完成后重新加入的待办排到末尾。进入 Todo 时保留左右两侧布局，右侧待选网页拖入 Todo 内容区域时不产生操作。

使用用户提供的 fluid-prism 为整个页面提供浅色流体背景、鼠标波纹和色散，并结合面板光泽及悬浮反馈增强质感。正文、按钮和待办行保持清晰，点击、输入和拖拽正常工作。

## User Stories

1. 作为用户，我希望从右侧待选区域拖入网页即可创建收藏链接，以便一次操作完成日常收集。
2. 作为用户，我希望收藏块中不再出现手动添加链接按钮或表单入口，以便使用统一的收集方式。
3. 作为用户，我希望空收藏块也不出现“添加第一个链接”等手动新增入口，以便空状态与正常收集方式一致。
4. 作为用户，我希望移除“收藏当前窗口”的批量收藏按钮及弹窗，以便页面只保留拖入收藏这一日常新增方式。
5. 作为用户，我希望拖入时直接采用网页标题、网址和图标，以便无需重复填写信息。
6. 作为用户，我希望拖入后备注初始为空且不弹出补充表单，以便收集过程保持连续。
7. 作为用户，我希望收藏成功保存到本地后关闭被拖入的原浏览器标签页，以便收集后减少打开的标签页。
8. 作为用户，我希望空收藏块和折叠收藏块仍能接收待选网页，以便快速放入目标位置。
9. 作为用户，我希望相同网址仍能形成相互独立的收藏链接，以便按不同用途整理。
10. 作为用户，我希望右侧继续展示当前窗口可收藏的普通网页，以便收集范围清楚且实时更新。
11. 作为用户，我希望抓住链接卡片的任意非控件区域即可拖动，以便不用寻找拖拽手柄。
12. 作为用户，我希望收藏块使用整体区域拖拽排序，以便与其他对象的拖拽方式一致。
13. 作为用户，我希望空间条目使用整体区域拖拽排序，以便直接调整导航顺序。
14. 作为用户，我希望待选网页条目使用整体区域拖动，以便直接把网页放入收藏块。
15. 作为用户，我希望所有可拖拽对象都不展示专用拖拽图标，以便页面保持简洁。
16. 作为用户，我希望拖动收藏块内的链接时只移动该链接，以便嵌套对象不会被误拖。
17. 作为用户，我希望对象内部的按钮、输入和折叠操作仍能正常使用，以便整体拖拽不干扰其他操作。
18. 作为用户，我希望点击打开链接与拖动链接能够正确区分，以便拖拽结束时不会误开网页。
19. 作为用户，我希望链接仍可在同空间收藏块之间移动，并保持跨空间移动限制，以便整理规则稳定。
20. 作为用户，我希望没有备注的收藏链接直接留空，以便不被“还没有备注”等重复文字干扰。
21. 作为用户，我希望已有备注继续完整展示，清空备注后恢复留空，以便备注只呈现我填写的内容。
22. 作为用户，我希望搜索和其他展示收藏备注的视图也不填充空备注提示，以便各处展示一致。
23. 作为用户，我希望 Todo 使用常见的纵向待办清单，以便从上到下逐项处理内容。
24. 作为用户，我希望点击 Todo 标题在新标签页打开对应网页，以便处理待办时保留工作台。
25. 作为用户，我希望每行有清晰的完成操作，以便快速移除已处理内容。
26. 作为用户，我希望完成后条目立即离开 Todo、原收藏的待办标记熄灭，以便列表只包含当前待处理内容。
27. 作为用户，我希望完成 Todo 后原收藏链接仍然保留，以便之后继续访问或再次加入待办。
28. 作为用户，我希望 Todo 行不再出现编辑、删除、移动、定位等额外操作，以便专注打开、完成和排序。
29. 作为用户，我希望抓住 Todo 行的非控件区域即可上下拖动，以便直接调整处理顺序。
30. 作为用户，我希望 Todo 汇集全部空间中标记点亮的有效收藏链接，以便在同一清单处理所有待办。
31. 作为用户，我希望可以调整来自不同空间和收藏块的 Todo 行的相对位置，以便按当前优先级排列。
32. 作为用户，我希望调整待办顺序不改变原收藏的位置和所属关系，以便处理顺序与收藏整理相互独立。
33. 作为用户，我希望调整收藏位置不改变已有待办顺序，以便两种整理方式互不干扰。
34. 作为用户，我希望重开页面或浏览器后保留待办顺序，以便继续之前的处理进度。
35. 作为多设备用户，我希望待办顺序随现有收藏数据同步，以便在其他设备继续使用相同顺序。
36. 作为用户，我希望新加入的待办排到当前清单末尾，以便已有优先级保持稳定。
37. 作为用户，我希望完成后从收藏处重新加入的待办排到末尾，以便将它视为新一轮待处理内容。
38. 作为用户，我希望同网址的不同收藏拥有独立的待办标记和排序身份，以便完成其中一项不影响另一项。
39. 作为已有数据的用户，我希望更新后原有待办都能显示并获得稳定顺序，以便升级不损坏收藏或待办状态。
40. 作为用户，我希望切换 Todo 时右侧待选区域仍然保留，以便页面结构和内容宽度不突然变化。
41. 作为用户，我希望把右侧网页拖入 Todo 内容区域时没有效果，以便它不会误建收藏、待办或打开网页。
42. 作为窄窗口用户，我希望 Todo 延续其他页面的待选区域抽屉规则，以便各页面使用一致的布局。
43. 作为用户，我希望移除“改动自动保存”和“一点点收集，一点点生长”等常驻提示，以便减少视觉噪声。
44. 作为用户，我希望口号、问候、引言和重复操作教学也得到清理，以便整个页面保持简洁。
45. 作为用户，我希望操作名称、必要空状态、输入校验和权限或同步错误仍然清楚，以便知道下一步如何处理。
46. 作为用户，我希望内容改动继续自动保存，以便减少提示文案后仍可放心使用。
47. 作为用户，我希望整个页面保留现有浅色主调，以便视觉升级仍符合我的配色偏好。
48. 作为用户，我希望使用 fluid-prism 呈现覆盖全页的流体背景，以便页面具有明显的动态视觉效果。
49. 作为用户，我希望移动鼠标时能看到波纹和色散反馈，以便流体效果能够被实际感知。
50. 作为用户，我希望面板、卡片和按钮配合光泽及悬浮反馈，以便视觉风格统一。
51. 作为用户，我希望文字和 Todo 行保持清晰稳定，以便动态背景不影响阅读。
52. 作为用户，我希望视觉层不拦截点击、滚动、输入和拖放，以便页面美化后仍能顺畅使用。
53. 作为用户，我希望切换页面、调整窗口和反复打开新标签页时效果正常，以便不会出现重复覆盖、错位或卡死。
54. 作为用户，我希望动效不可用时仍能使用收藏与 Todo，以便视觉增强不成为功能使用的前提。
55. 作为已有数据的用户，我希望备份、导入和既有同步继续保留收藏、备注、待办标记及新增顺序，以便升级后仍能恢复和迁移自己的数据。
56. 作为用户，我希望移除卡片底部剩余的移动图标及其撑起的空白，以便卡片更加紧凑。
57. 作为用户，我希望拖动时在预期落点看到占位元素，以便清楚判断放下后的位置。
58. 作为用户，我希望已有收藏对象的拖动预览保留完整内容与宽高，以便整理时保持对象识别。
59. 作为用户，我希望待选网页进入中间收藏内容区域后立即呈现为链接卡片，并在收藏块中显示插入占位，以便松手前明确最终形态和顺序。
60. 作为用户，我希望通过侧栏或 `/` 打开搜索弹窗，以便搜索时保留当前页面，定位结果后再跳转到原收藏块。
61. 作为用户，我希望待选条目的底色与背景更有区分，以便清楚识别可收集的网页。
62. 作为用户，我希望把待选网页或已有链接卡片拖到收藏块上边或下边，停留 2 秒后通过发光线确认建块位置，以便松手直接创建“新收藏”。
63. 作为用户，我希望在计时未完成、离开触发带或取消拖动时不创建收藏块，以便整理过程中不产生多余内容。
64. 作为用户，我希望快捷建块移动已有收藏链接，并保留变空的原收藏块，以便继续使用原有组织结构。
65. 作为用户，我希望没有收藏块时先通过按钮创建第一个块，以便快捷建块始终依附于已有收藏块。

## Implementation Decisions

- 交付目标是现有 Chrome 新标签页扩展，沿用 React、TypeScript、pnpm 和既有样式组织。主要修改职责包括页面布局与文案、收藏展示、待选区域、Todo 列表、拖放路由、领域操作及数据读写兼容；不按组件新增分散的业务接口。
- 日常新增收藏唯一入口是待选区域拖入已有收藏块，或在已有收藏块边缘触发快捷建块落点后松手。移除手动新增链接和点击批量收藏的界面入口及其专用弹窗流程；没有收藏块时先使用已有按钮创建收藏块，空状态不接收拖放。窄窗口沿用同样规则。已有收藏的编辑、备份导入及数据源迁移继续承担各自既有职责，不视为日常手动新增入口。
- 待选网页拖入时直接保存标题、网址和图标，备注为空，不要求表单或确认；本地保存成功后关闭被拖入的原标签页，不等待云端同步。保存失败保留原页；关闭失败保留已保存的收藏并提示。仅收集当前窗口中的 HTTP/HTTPS 网页，重复网址作为独立收藏保留，折叠收藏块接收后展开。
- 空间条目、收藏块、链接卡片、待选网页条目和 Todo 行统一使用对象整体作为拖拽区域，移除专用手柄及拖拽图标。非控件区域可启动拖拽，内部交互控件保持原有功能；链接的浏览器原生拖动不得替代应用中的条目拖动。
- 用户在实施开始后追加指定使用 dnd-kit。统一拖拽上下文处理鼠标、触摸与键盘输入，提供误触阈值、拖动预览、排序过渡和有效落点反馈，不恢复专用手柄。
- 用户在实施验收中进一步要求：移除卡片底部剩余的移动按钮，空备注不保留额外底部行；已有收藏对象预览保留完整内容与原始宽高，排序落点使用等尺寸占位。2026-11-12 调整：待选网页进入中间收藏内容区域后预览立即变为链接卡片，在收藏块内与已有链接一样显示占位并选择插入顺序，不能始终追加到末尾。
- 搜索收藏改为弹窗，侧栏入口和 `/` 快捷键继续可用；关闭后保留当前页面，定位结果时关闭弹窗并切换到原收藏块。
- 拖放处理必须识别实际拖动对象和目标用途，区分收藏块排序、收藏链接移动、待选网页收集和 Todo 排序；处理嵌套事件，避免拖动子项带动父项或一次投放触发多个动作。保持现有同空间跨块移动与跨空间限制。
- Todo 使用专门的纵向列表呈现，不继续复用带管理操作的链接卡片。每行仅包含必要识别信息、可打开的标题及完成控件，并支持整行拖动排序；不提供编辑、删除、移动、定位、独立创建任务或完成历史。
- 完成等价于熄灭收藏链接自身的待办标记，立即从列表移除但保留原收藏。再次加入仍在原收藏处点亮标记，不新增任务副本。
- 引入独立的全局待办顺序，排序对象使用收藏链接身份而非网址。Todo 排序不修改收藏顺序、所属收藏块或空间；已有待办再次收到相同的加入状态不应被无故重排，新加入及完成后重新加入排末尾。排序由应用操作维护并进入本地持久化与现有同步，不仅保存在页面状态中。
- 为没有待办顺序信息的历史本地数据、云端数据及备份提供兼容读取和确定性初始顺序，保留原有收藏、备注和待办标记。新增顺序参与导入、导出、合并和冲突处理；具体字段、格式版本及迁移实现由开发确定，不将新增需求变成旧数据损坏错误。
- Todo 保留左右两侧区域以及现有响应式抽屉规则。待选网页或其他非 Todo 行拖入 Todo 内容区不创建内容、不触发收藏移动、不导航当前页、不打开网页，也不展示可接收该类拖放的反馈。只有现有待办行之间的有效拖放会修改待办顺序。
- 所有备注展示直接使用实际备注内容，空备注不替换成“还没有备注”“无备注”等提示。编辑表单的必要字段名称与无障碍标签可以保留，不用新占位文案填满展示区域。
- 清理范围覆盖主页面、导航、待选区域、空状态、编辑弹窗、设置和首次连接页面中的口号、问候、引言、装饰说明和重复自动保存说明。保留必要操作名称、精简空状态、输入校验、影响数据的确认、权限与连接错误、同步失败和冲突状态；保留 ADR 0002 要求说明的云端历史与回收站保留区别。
- 使用用户指定的 fluid-prism 库，基于当前奶白、浅灰及低饱和强调色增强整体视觉；不切换到深色蓝紫主题。全页背景承担流体纹理、鼠标波纹和色散，真实文本与交互控件位于可正常阅读和操作的界面层，面板配合光泽与悬浮反馈。
- 视觉集成以 Chrome 可用的 WebGL 路径为优先，不要求新增 WebGPU 路径或 DOM 截图系统。库及所需视觉资源随扩展构建交付，具体锁定版本、参数和纹理选择在实施时核实；不以纯 CSS 动画替代实际库集成。无需为视觉效果新增用户配置或主题编辑器。
- 动效初始化、销毁、窗口变化和失败处理属于视觉层职责；重复挂载不能留下重复画布、监听或渲染循环，初始化失败保持可用的浅色页面。动效层不得阻挡上层操作或延迟本地内容展示。性能调节采用实现时测量结果，不宣称尚未约定的帧率或设备覆盖范围。
- 尊重 ADR 0002 对主要同步方式的调整：夸克独立版本保存与校验为主，WebDAV 作为既有数据兼容和迁移入口；沿用本地优先、离线编辑、账号隔离及冲突保留规则。待办顺序作为新增业务状态接入这些边界，不新建同步系统。

## Testing Decisions

- 用户于 2026-11-10 明确确认沿用现有真实 Chrome 新标签页浏览器流程：实际点击与拖拽、重开后的排序保存、受控服务中的跨设备顺序，以及桌面和窄窗口的视觉与操作验证。
- 以完整用户工作流作为一个主要测试边界，覆盖新标签页、真实扩展后台、本地持久化和受控外部同步服务。只断言可见行为与持久化结果，不断言组件树、内部函数调用、CSS 类名、Query 键、顺序字段名称或 shader 实现细节。
- 复用现有 Playwright 测试、隔离 Chrome 用户配置、受控 HTTPS 网页和夸克/WebDAV 测试服务。现有先例已覆盖待选拖入、空间/收藏块/链接排序、Todo 完成、重开持久化、同步、冲突、备份和桌面/窄窗口截图；本轮扩展这些先例，无需创建组件级测试边界。
- 现有测试中的手动新增辅助流程改为打开受控网页后从待选区域拖入；批量收藏成功用例改为确认入口移除，并继续通过有效拖入创建所需数据。不得保留仅供测试调用的手动添加入口或绕过界面直接调用内部新增操作来代替核心验收。
- 收藏验收覆盖所有手动与批量入口移除、空块/折叠块拖入、元信息正确、无表单、无备注占位、本地保存成功后原网页关闭、重复网址独立，以及编辑后清空备注。保存失败时原页仍在；关闭失败时收藏仍在且有提示。搜索等其他展示位置同样检查空备注行为。
- 拖拽验收从对象的非手柄区域发起真实浏览器拖放，分别覆盖空间、收藏块、链接、待选网页和 Todo 行。检查父子嵌套不误拖、内部按钮及折叠仍可用、点击标题可打开而拖动不会误开、同空间移动与跨空间限制继续生效。
- Todo 验收覆盖纵向列表、标题新标签打开、完成后移出而原收藏保留、额外操作消失、无完成历史、跨空间来源条目混合调序，以及重复网址的独立身份。验证新加入和完成后重新加入位于末尾。
- 排序验收同时比较 Todo 顺序与原收藏位置，确认两者互不影响；覆盖页面重开、浏览器重启、离线保存后重连、同步到第二个客户端及备份恢复。使用来自不同空间和收藏块的多条待办，避免仅在一个收藏块内验证导致顺序耦合漏检。
- 历史数据验收使用不含新增顺序信息的本地、云端或备份样本，确认正常读取、所有有效待办可见、初始顺序稳定，且完成、重排、同步后可持续保存。新增顺序相关并发修改沿用既有合并和冲突保留语义，不静默丢弃收藏或标记。
- 布局与无效拖放验收覆盖空间页和 Todo 切换时左右区域保留、同一窗口宽度下主体布局稳定、窄窗口抽屉可用；右侧网页拖入 Todo 不新增内容、不打开网页、不导航或误改排序。
- 提示验收检查被点名的文案、常驻口号与重复说明已移除，同时构造输入错误、连接失败或同步失败，确认必要反馈仍可见；不把所有提示元素一律隐藏当作实现。
- 视觉验收在实际启用 fluid-prism 的 Chrome 中移动鼠标，观察浅色全页流体、波纹和色散，并检查文字、面板及悬浮反馈。保存桌面和窄窗口截图，结合实时交互验证；单张静态截图不能证明鼠标动效正常。
- 动效开启时验证点击、输入、滚动、拖拽和弹窗；检查窗口变化、页面切换及关闭重开后无重复覆盖或明显停滞。模拟视觉初始化不可用，确认收藏和 Todo 仍可操作。动态效果不采用逐帧像素一致断言，也不编造未测量的性能结论。
- 功能实现交付时执行 TypeScript 类型检查、Chrome 生产构建及与变更相关的浏览器验收，既有同步和持久化回归应继续通过。当前规格交付仅检查文档完整性和发布内容，不表示以上功能测试已经执行或通过。

## Out of Scope

- 独立手动任务、已完成历史、提醒、截止日期、周期任务和其他 Todo 管理功能。
- 在 Todo 中编辑、删除、定位或移动收藏，以及把待选网页拖入 Todo 创建内容。
- 手动新增链接、点击批量收藏的替代入口、批量拖选或新增导入类型。
- 深色主题、深色蓝紫霓虹方向、主题编辑器、动效参数设置面板和 WebGPU 专项适配。
- 真实正文 DOM 的截图、折射或随鼠标扭曲系统，以及网页全文抓取。
- 收藏链接跨空间移动、网址去重或跨窗口汇总。
- 重做同步架构、云端历史清理策略、账号体系、浏览器权限体系或回收站期限。
- Firefox、Edge 专项适配、扩展商店发布，以及未经测量的全设备性能承诺。
