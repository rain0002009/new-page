# 完善待选区域：一键收藏、单条关闭与浏览器同步排序

## Problem Statement

用户需要从待选区域快速整理当前窗口中打开的网页。目前只能逐个拖入收藏块，无法一次收集整个待选区域，也无法直接从待选条目关闭浏览器标签页。待选列表虽然会跟随浏览器标签栏的顺序更新，却不能反过来通过上下拖动整理浏览器标签页。

用户希望一次点击即可创建带精确时间的新收藏块，保存成功后减少打开的标签页；也希望在同一处关闭或排序网页，避免在收藏工作台和浏览器标签栏之间反复操作。

## Solution

在待选区域标题处增加一键收藏图标按钮，将点击时当前窗口待选区域的全部网页按当时顺序收集为一个新收藏块。新块命名为“收藏 YYYY-MM-DD HH:mm:ss”，采用点击时的本机时间，放到当前选中空间顶部并展开。用户从 Todo、设置等页面发起时，使用最近选中的空间，保存成功后切回该空间查看结果。空空间也支持该操作。

新收藏块及全部收藏链接成功保存到本地后，再关闭这次收集的准确原标签页，不等待云端同步。保存失败时不关闭任何原页；关闭失败时保留完整收藏并提示。

每个待选条目增加关闭图标，点击直接关闭对应浏览器标签页。待选条目支持上下拖动排序并同步移动浏览器标签页，同时保留拖入已有收藏块和快捷建块的用途。置顶状态保持不变，置顶标签与非置顶标签分别排序。特殊页面继续隐藏，其位置遵循浏览器正常移动规则。

## User Stories

1. 作为用户，我希望在待选区域标题处看到一键收藏图标，以便快速收集当前待选网页。
2. 作为用户，我希望一次点击就完成建块和收藏，以便不必逐条拖动或填写名称。
3. 作为用户，我希望一键收藏只处理本窗口待选区域展示的 HTTP/HTTPS 网页，以便收藏范围与眼前列表一致。
4. 作为用户，我希望其他窗口和隐藏特殊页面不被收藏或关闭，以便本次整理只影响当前工作上下文。
5. 作为用户，我希望新块名称使用“收藏 YYYY-MM-DD HH:mm:ss”，以便看到本次收藏的具体时间。
6. 作为用户，我希望时间取自点击时的本机时间并精确到秒，以便名称反映实际发起时刻。
7. 作为用户，我希望新收藏块出现在当前选中空间的顶部，以便立即找到收集结果。
8. 作为用户，我希望新收藏块自动展开，以便直接查看已保存的链接。
9. 作为用户，我希望从 Todo 或设置页发起时使用最近选中的空间，以便保持明确的收藏归属。
10. 作为用户，我希望跨页面收藏成功后切回目标空间，以便立即确认结果。
11. 作为用户，我希望空空间也能一键收藏，以便直接创建第一个收藏块。
12. 作为用户，我希望新块链接顺序与点击时的待选顺序相同，以便保留整理结果。
13. 作为用户，我希望收藏保存点击时的标题、网址和图标，以便记录当时选择的网页。
14. 作为用户，我希望操作期间新开的标签页不被本次收藏或关闭，以便范围不会悄然扩大。
15. 作为用户，我希望相同网址的多个标签分别保存为独立收藏链接，以便保留不同条目的身份和位置。
16. 作为用户，我希望置顶网页也参与一键收藏，以便收藏内容与完整待选列表一致。
17. 作为用户，我希望新链接备注为空且待办标记关闭，以便收集不附带额外任务状态。
18. 作为用户，我希望空待选区域禁用一键收藏，以便不会创建空块或误报成功。
19. 作为用户，我希望执行期间重复点击不会重复提交，以便一次操作只创建一个收藏块。
20. 作为用户，我希望同一秒内先后完成的独立收藏可以同名，以便已有内容不会被覆盖。
21. 作为用户，我希望新块和全部链接保存成功后才关闭原页，以便收藏不会因保存失败而丢失。
22. 作为离线用户，我希望本地保存成功即可关闭原页，以便不必等待云端恢复。
23. 作为用户，我希望本地保存失败时不留下部分收藏、不关闭原页并提示错误，以便安全重试。
24. 作为用户，我希望关闭动作按原标签页身份执行，以便同网址的其他标签不会被误关。
25. 作为用户，我希望收藏期间原页已关闭时仍保留快照收藏，以便正常完成此次收集。
26. 作为用户，我希望原页已经跳转时保留新页面并提示，以便不会误关后来打开的内容。
27. 作为用户，我希望原页已经移出原窗口时保留该页并提示，以便不干扰另一个窗口。
28. 作为用户，我希望部分原页关闭失败时保留完整收藏并提示，以便知道内容已保存且哪些关闭未完成。
29. 作为用户，我希望关闭失败不会自动再次建块，以便不会生成重复收藏。
30. 作为用户，我希望每个待选条目都有关闭图标，以便直接移除不需要的浏览器标签页。
31. 作为用户，我希望点击关闭只作用于对应标签页，以便重复网址的其他页继续保留。
32. 作为用户，我希望单条关闭直接生效且不增加应用确认弹窗，以便连续整理网页。
33. 作为用户，我希望关闭操作不先收藏也不进入应用回收站，以便它与删除收藏内容的含义清楚区分。
34. 作为用户，我希望浏览器自身的离开页面确认继续生效，以便需要确认的页面遵循浏览器行为。
35. 作为用户，我希望单条关闭失败时条目仍在并显示提示，以便能够重新处理。
36. 作为用户，我希望置顶标签也有关闭入口，以便在待选区域完成同样的整理操作。
37. 作为用户，我希望关闭按钮有独立点击区域，以便点击时不误触拖动或收藏。
38. 作为用户，我希望通过上下拖动调整待选顺序，以便在收藏前安排网页的先后次序。
39. 作为用户，我希望拖动时看到插入位置，以便在松手前预判结果。
40. 作为用户，我希望松手后的浏览器标签顺序与待选区域一致，以便两个位置反映同一次整理。
41. 作为用户，我希望可以将标签移动到同类标签的开头、中间和末尾，以便自由安排顺序。
42. 作为用户，我希望向上和向下移动都能准确落位，以便排序不出现偏移。
43. 作为用户，我希望排序保持置顶状态，以便整理顺序不会意外置顶或取消置顶。
44. 作为用户，我希望置顶标签只在置顶标签间排序、普通标签只在普通标签间排序，以便保持浏览器的两类边界。
45. 作为用户，我希望跨越置顶边界时不能提交，以便不会产生浏览器无法保持的预览结果。
46. 作为用户，我希望隐藏特殊页面遵循正常标签移动规则，以便可见网页移动时不强制固定特殊页的原编号。
47. 作为用户，我希望“A、设置页、B”中把 B 放到 A 前得到“B、A、设置页”，以便该场景有可预测的结果。
48. 作为用户，我希望取消拖动或无效松手不改变浏览器顺序，以便可以安全放弃排序。
49. 作为用户，我希望在浏览器标签栏排序后待选列表随之更新，以便不会看到过期顺序。
50. 作为用户，我希望排序失败后按浏览器实际状态重新显示并提示，以便界面不会留下虚假的顺序。
51. 作为用户，我希望排序期间标签被外部关闭、移动或改变置顶状态时重新读取实际状态，以便不会按过期位置移动错误对象。
52. 作为用户，我希望排序、取消或失败不触发收藏和关闭，以便每种操作有明确结果。
53. 作为用户，我希望原有拖入收藏块和快捷建块继续可用，以便新增排序不破坏收集流程。
54. 作为用户，我希望鼠标、触摸和键盘都能使用这些交互，以便沿用现有输入方式。
55. 作为窄窗口用户，我希望待选抽屉与桌面侧栏功能一致，以便窗口宽度不影响整理能力。
56. 作为用户，我希望图标按钮提供悬停说明和无障碍名称，以便理解用途并通过辅助技术操作。
57. 作为用户，我希望重开页面后仍能看到本次收藏及其排列，以便结果已经可靠保存。
58. 作为多设备用户，我希望新块和链接沿用现有同步保存，以便其他设备能够读取本次收藏。
59. 作为用户，我希望浏览器标签页身份和实时顺序不作为收藏同步数据，以便收藏与当前浏览器窗口各自保持正确含义。
60. 作为用户，我希望现有收藏块、收藏链接和 Todo 的排序继续正常，以便此次改动只扩展待选整理能力。

## Implementation Decisions

- 交付目标为现有 Chrome 新标签页扩展，沿用现有 React、TypeScript、dnd-kit、UnoCSS utilities 与 tailwind-variants。界面遵循项目现有风格和样式约定。
- 使用领域术语“待选区域”“打开的标签页”“空间”“收藏块”“收藏链接”和“一键收藏”。浏览器标签页身份与收藏链接身份分离，网址不能作为唯一标识。
- 修改待选区域展示与操作模块、当前窗口标签页适配模块、拖动协调模块、工作台导航与反馈模块，以及本地收藏操作和持久化入口；复用已有同步流程。
- 当前待选来源只包含本窗口 HTTP/HTTPS 网页，包括置顶网页，按浏览器顺序排列。继续监听浏览器创建、关闭、更新、排序及跨窗口变化。
- 标签页适配在临时交互状态中提供可靠的标签页身份、来源窗口、置顶状态及实际位置，支持安全关闭和移动。这些信息不进入收藏持久化、导出、备份或云端同步格式。
- 一键收藏在点击时固定目标空间、时间和待选快照，包含标题、网址、图标及顺序。新名称严格采用“收藏 YYYY-MM-DD HH:mm:ss”，按本机时间格式化；不同收藏块允许同名，以独立身份区分。
- 一次本地收藏操作创建一个位于目标空间顶部的新块及全部链接，支持目标空间尚无收藏块的情况。每条链接独立生成身份、备注为空、待办标记关闭，不按网址去重。
- 新块及全部链接必须一起成功保存到本地；失败时不留下部分新块或部分链接，不关闭原页。执行期间阻止重复提交，但不把同名当作重复操作依据。
- 本地保存成功后展开新块并显示目标空间，再关闭此次快照对应的准确原标签页，不等待云端同步。沿用 ADR 0002 的本地优先与现有同步、账号隔离和冲突处理约定。
- 关闭前检查原标签页身份、网址及来源窗口：已关闭视为完成，已跳转或移出原窗口则保留并提示。部分关闭失败保留完整收藏并反馈，不回滚收藏、不自动重新建块，也不影响快照之外的标签页。
- 单条关闭是直接的浏览器标签页关闭操作，不先收藏、不进入应用回收站、不增加应用确认弹窗；保留浏览器自身的离开页面确认。失败时按实际状态保留条目并提示。
- 一键收藏与单条关闭按钮具备悬停说明、无障碍名称、独立点击区域和明确的执行状态，避免按钮点击启动条目拖动。空待选区域禁用一键收藏。
- 待选区域内部增加上下排序落点、插入预览和提交动作，保留拖出待选区域进入收藏块及快捷建块落点的既有行为；排序与收藏提交明确区分。
- 排序只允许相同置顶状态的标签页之间进行，不改变置顶属性，跨边界时不允许落下。真实移动在有效松手后执行，取消或无效松手不移动、不收藏、不关闭。
- 按稳定身份解析浏览器最新位置并移动目标标签页，遵循浏览器正常移动规则。隐藏特殊页不固定在原绝对槽位；“A、设置页、B”将 B 放到 A 前应变为“B、A、设置页”。
- 浏览器实际状态是最终依据。排序失败时提示并重新查询；提交期间原页被外部关闭、移动或改变置顶状态时重新校验并刷新，不按过期索引操作，不保留未实际完成的本地顺序。
- 桌面侧栏和窄窗口抽屉共享相同语义，沿用鼠标、触摸与键盘能力。具体图标、尺寸与样式由实施时按现有规范选择。
- 一键收藏允许空空间，与已有快捷建块落点分别处理；后者仍要求空间原先已有收藏块。既有单条拖入收藏的保存及关闭行为继续适用。
- 本规格替代旧批量收藏需要命名弹窗、保存后保留原页的约定。实施时同步修改旧描述和“无批量入口”的旧测试期待。
- 无需新增云端数据格式或持久化浏览器标签页关联。本轮属于可逆的交互扩展，没有新的架构取舍需要 ADR。

## Testing Decisions

- 用户已确认沿用现有最高层验收边界：通过真实 Chrome 扩展的新标签页界面执行点击、鼠标/触摸/键盘拖动，验证可见结果、浏览器标签页实际状态及重开后的本地数据。本次不引入新的产品测试边界，不重复访谈。
- 测试覆盖待选区域、浏览器标签页适配、拖动协调、空间导航、新收藏块及链接本地保存，并通过现有外部受控 HTTPS 同步服务验证同步结果。通过用户可观察行为断言，不镜像组件、Hook 或 reducer 实现。
- 现有先例包括真实扩展加载、受控网页、标签拖入已有收藏块与快捷建块、同网址独立收藏、置顶标签、原页关闭或跳转、本地写入失败、关闭失败、窄屏以及键盘与触摸验收。复用现有浏览器夹具及必要的故障注入，不以直接调用内部排序或收藏函数代替用户操作。
- 一键收藏正常流程验证精确名称格式、点击时本机时间、目标空间、顶部插入、展开、页面切换、链接顺序及元信息、重复网址、置顶网页、空备注和关闭的待办标记。覆盖空空间、Todo/设置等非空间页，以及隐藏特殊页和其他窗口排除。
- 使用受控时间验证精确到秒、点击时刻与保存完成时刻的区别、同秒独立同名收藏；通过受控执行时序验证连续点击仅提交一次、操作期间新开的网页不被收集或关闭。
- 验证新块及全部链接可靠落地后才关闭原页；注入本地失败确认无部分写入且原页全保留；离线和云端失败不阻断本地成功后的关闭；部分关闭失败不回滚或重复建块。
- 覆盖快照生成后原页已关闭、跳转或移出窗口，验证快照收藏仍完整，变化后的页面被保留并有清楚提示；相同网址的其他页不被误关。
- 单条关闭验证准确身份、置顶及重复网址、浏览器侧实际关闭与待选更新、不新增收藏或应用回收站内容、失败提示，以及按钮点击不触发拖动。浏览器自身的离开页面确认保持浏览器行为。
- 排序必须通过真实用户输入完成，校验待选区域与浏览器实际标签序列，覆盖首尾和中间插入、双向移动、同类置顶排序、拒绝跨置顶边界，以及“A、设置页、B”示例。
- 覆盖浏览器侧排序反向刷新、标签跨窗口移动、拖动取消、无效松手、移动失败、操作期间外部关闭/移动/改变置顶状态；确认最终展示为浏览器实际顺序，且没有意外收藏或关闭。
- 验证桌面侧栏与窄屏抽屉的按钮、插入反馈、鼠标/触摸/键盘交互及无障碍名称；回归原有拖入已有收藏块、快捷建块、收藏块和链接排序、Todo 排序及其取消行为。
- 重开新标签页和浏览器验证新收藏块、链接及其顺序仍在；沿用既有同步夹具验证这些收藏进入现有同步，而临时浏览器身份与位置不进入同步、备份或导出内容。
- 实施完成后执行 TypeScript 类型检查、Chrome 生产构建及相关真实扩展验收。本次任务仅形成并发布规格，未宣称上述新增功能验收已经通过。

## Out of Scope

- 全浏览器多窗口汇总、跨窗口拖动整理、浏览器标签组整理或完整会话恢复。
- 跨越置顶边界时自动置顶或取消置顶；将隐藏特殊页面固定在原编号位置。
- 收藏浏览器设置页、扩展页、新标签页或其他非 HTTP/HTTPS 页面。
- 一键收藏时弹出命名表单、网址去重、名称唯一约束、批量拖选或一次拖动多个标签页。
