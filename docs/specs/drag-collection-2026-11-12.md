# 优化拖拽收集：关闭原标签页、卡片占位排序与停留快捷建块

后续调整：用户于 2026-11-12 确认 [交互动效优化](motion-polish-2026-11-12.md)，将下文快捷建块的 2 秒阈值改为 0.6 秒，仅进入落点时显示停留提示与进度，并补充形态、落位及布局过渡。下文其余行为继续适用。

## Problem Statement

用户将打开的标签页从待选区域拖入收藏块后，浏览器中的原标签页仍然保留，收集网页没有减少打开的标签页。待选条目的底色与流体背景过于相似，也不容易辨认。

待选网页在中间区域拖动时仍维持待选条目的外观，直到松手后才过渡为链接卡片；放到已有卡片上时又始终追加到收藏块末尾。用户无法在拖动过程中清楚预判最终形态和插入顺序。

用户整理网页时还需要在已有收藏块之前、之间或之后快速建立新收藏块，并直接把当前拖动的网页或收藏链接放进去。普通拖拽与新建之间需要明确的触发条件，避免经过空白或短暂停留就误建收藏块。

## Solution

待选网页进入空间页的整个中间收藏内容区域后，拖动预览立即变为链接卡片；进入已有收藏块时显示与普通链接卡片一致的插入占位，允许放到开头、中间或末尾。收藏成功保存到本地后关闭被拖动的原浏览器标签页，不等待云端同步。适度增强待选条目的底色，使其与背景清楚区分。

将已有收藏块之间的间隙，以及第一块上方和最后一块下方，定义为快捷建块落点。拖动待选网页或已有链接卡片进入落点时先显示淡线；在同一落点连续停留 2 秒后，淡线变成发光线并提示“松手新建收藏块”。此时松手，在指示位置创建并展开名为“新收藏”的收藏块，将当前网页保存或将已有链接移动进去。

普通空白区域不接收拖放；没有收藏块的空间也不提供快捷建块落点，用户必须先通过已有按钮创建至少一个收藏块。Todo、搜索、空间排序和整个收藏块的排序继续承担原有用途。

## User Stories

1. 作为用户，我希望把待选网页拖入已有收藏块即可收集，以便继续使用统一的日常新增入口。
2. 作为用户，我希望收集时采用拖动开始时的网页标题、网址和图标，以便保存自己选中的网页。
3. 作为用户，我希望新收藏链接的备注为空且不弹出表单，以便连续收集网页。
4. 作为用户，我希望待选网页进入空间页中间收藏内容区域时立即变成链接卡片预览，以便提前看到收藏后的形态。
5. 作为用户，我希望中间空白处也能呈现卡片预览，以便拖动形态不会只在命中已有卡片时才变化。
6. 作为用户，我希望卡片预览和有效接收反馈能够区分，以便预览变为卡片后仍能判断哪些地方允许松手。
7. 作为用户，我希望待选网页拖入已有收藏块时显示插入占位，以便判断松手后的具体位置。
8. 作为用户，我希望待选网页可以插入收藏块开头、中间或末尾，以便收集时直接安排顺序。
9. 作为用户，我希望待选网页与已有链接卡片采用一致的占位和排序反馈，以便使用同样的整理方式。
10. 作为用户，我希望空收藏块也能接收网页，以便不必先放入其他链接。
11. 作为用户，我希望折叠收藏块仍可接收网页且成功后展开，以便确认刚保存的内容。
12. 作为用户，我希望相同网址仍可保存为独立收藏链接，以便按不同用途组织网页。
13. 作为用户，我希望收藏成功保存到本地后关闭原标签页，以便减少浏览器中打开的标签页。
14. 作为用户，我希望只关闭被拖动的那个标签页，以便其他打开相同网址的标签页继续保留。
15. 作为用户，我希望置顶标签页也遵循收集成功后关闭的规则，以便收集行为一致。
16. 作为离线用户，我希望本地保存成功即可关闭原标签页，以便不必等待云端连接恢复。
17. 作为用户，我希望本地保存失败时保留原标签页并提示错误，以便网页不会因收集失败而丢失。
18. 作为用户，我希望关闭原标签页失败时保留已保存的收藏并提示，以便知道收藏已经完成。
19. 作为用户，我希望原标签页在拖动期间已经关闭时仍完成收藏，以便保存当前拖动的信息。
20. 作为用户，我希望原标签页在拖动期间跳转后保留新页面并收到提示，以便不会误关刚打开的内容。
21. 作为用户，我希望待选区域继续只展示当前窗口中可收藏的普通网页，以便收集范围明确。
22. 作为用户，我希望待选条目底色比当前更明显，以便从流体背景上清楚辨认网页条目。
23. 作为用户，我希望增强底色后标题、图标和交互状态仍清晰，以便页面保持现有浅色视觉风格。
24. 作为用户，我希望拖动待选网页能够在已有收藏块边缘快速建块，以便一次拖拽完成建立分类和收集。
25. 作为用户，我希望拖动已有链接卡片也能快速建块，以便从现有收藏中拆出新的集合。
26. 作为用户，我希望两块之间的间隙可以作为快捷建块落点，以便直接插入到目标位置。
27. 作为用户，我希望第一块上方和最后一块下方也有快捷建块落点，以便在序列首尾创建收藏块。
28. 作为用户，我希望触发带不覆盖链接卡片，以便块内插入排序仍然容易操作。
29. 作为用户，我希望共享间隙只代表一个建块位置，以便不会因靠近上下不同块而切换目标。
30. 作为用户，我希望进入触发带先出现淡线，以便知道正在选择哪个建块位置。
31. 作为用户，我希望在同一位置连续停留 2 秒后才出现发光线，以便明确区分快捷建块和普通经过。
32. 作为用户，我希望发光时看到“松手新建收藏块”，以便理解接下来松手的结果。
33. 作为用户，我希望同一间隙内移动不重新计时，以便轻微移动不会打断意图。
34. 作为用户，我希望离开触发带后撤销发光并重置计时，以便已经离开的目标不会继续接收。
35. 作为用户，我希望换到另一间隙时重新计时，以便新位置需要独立确认。
36. 作为用户，我希望取消拖动后清除计时和反馈，以便取消不会留下新收藏块或关闭原标签页。
37. 作为用户，我希望未满 2 秒在触发带松手时取消操作，以便短暂停留不会误建收藏块。
38. 作为用户，我希望满 2 秒后仍须松手才创建，以便可以在提交前继续改变主意。
39. 作为用户，我希望滚动使拖动离开原落点后不再累计停留时间，以便指示位置始终与当前落点一致。
40. 作为用户，我希望松手后只创建一个收藏块并放入当前链接，以便一次拖放不会重复执行。
41. 作为用户，我希望新建收藏块直接命名为“新收藏”，以便无需填写名称即可继续整理。
42. 作为用户，我希望允许多个“新收藏”同名，以便连续快速建块不会被名称校验打断。
43. 作为用户，我希望新块直接展开且不弹出重命名，以便立即确认刚放入的内容。
44. 作为用户，我希望已有收藏链接通过移动进入新块并保留标题、备注及待办标记，以便整理不损失内容。
45. 作为用户，我希望原收藏块即使变空也继续保留，以便保留原有组织结构。
46. 作为用户，我希望建块或放入链接保存失败时不留下空新块或丢失已有链接，以便失败后仍能继续整理。
47. 作为用户，我希望普通空白区域松手取消，以便只有明确的有效落点能够改变收藏。
48. 作为用户，我希望没有收藏块时不触发拖入建块，以便先通过按钮建立第一个收藏块。
49. 作为用户，我希望 Todo 继续只处理待办排序，以便待选网页不会误建收藏或待办。
50. 作为用户，我希望搜索结果通过定位回到原收藏块后再整理，以便搜索弹窗不承担快捷建块。
51. 作为用户，我希望拖动整个收藏块仍只调整块顺序，以便不会被识别为拖动链接建块。
52. 作为用户，我希望空间排序、同空间跨块移动和跨空间限制继续正常，以便本轮改进符合既有整理规则。
53. 作为用户，我希望卡片内部按钮、输入与点击打开网页仍能正常使用，以便整体拖拽不干扰其他操作。
54. 作为用户，我希望鼠标、触摸与键盘拖拽都保留有效落点、计时与取消能力，以便继续使用已有输入方式。
55. 作为窄窗口用户，我希望待选抽屉中的拖入、卡片预览和快捷建块同样可用，以便窗口变窄后仍能收集。
56. 作为用户，我希望重开页面或浏览器后保留新块、链接及排列顺序，以便整理结果不会丢失。
57. 作为多设备用户，我希望新块、链接与顺序随现有同步保存，以便其他设备也能看到本次整理。
58. 作为用户，我希望移动收藏链接不改变既有待办顺序，以便收藏结构与待办优先级保持独立。

## Implementation Decisions

- 交付目标是现有 Chrome 新标签页扩展。主要修改待选区域、拖动预览、落点识别与占位、收藏块展示、浏览器标签页访问及本地收藏操作；沿用 React、TypeScript、dnd-kit 和现有持久化入口。
- 使用领域词汇“打开的标签页”“收藏链接”“链接卡片”和“快捷建块落点”。浏览器标签页与已保存收藏是不同对象；网址既不能替代标签页身份，也不能替代收藏链接身份。
- 待选来源在本次拖动生命周期中保留原标签页身份及拖动开始时的标题、网址、图标。浏览器标签页身份只用于当前收集后的关闭判断，不写入可同步收藏、导出或备份数据。
- 待选网页进入空间页整个中间收藏内容区域时即呈现卡片预览，无需先命中已有卡片。预览形态与接收资格独立；普通空白仍不能提交。
- 进入已有收藏块时使用与已有链接相同的插入占位，提交位置与占位一致，支持开头、中间和末尾；不再将待选来源固定追加到尾部。空块可接收，折叠块沿用拖动时展示内容、成功收集后展开的行为。
- 快捷建块仅适用于空间页，来源仅为待选网页或已有链接卡片。整个收藏块及空间的拖动保持原排序用途，Todo 只调整待办顺序，搜索结果不提供拖入或建块。
- 收藏块按当前空间的单列序列排列，块内卡片可以多列。快捷建块指向收藏块序列的插入位置，不引入多列收藏块或列内块顺序。
- 触发范围为收藏块之间现有的 24px 间隙、第一块上方 24px 和最后一块下方 24px 的区域，不覆盖链接卡片。相邻两块的共享间隙表示同一个位置。
- 进入触发带先显示淡线；在同一落点连续停留 2 秒后变为发光线，并提示“松手新建收藏块”。同一间隙内移动不重计时；离开、取消或切换间隙，立即撤销可提交状态与发光并重置计时。重新进入须重新等待。
- 中间内容独立滚动时，以当前可见落点判断停留；滚动使拖动离开原落点后不继续累计计时。沿用已有鼠标、触摸和键盘输入能力，保持有效落点、停留和取消语义一致。
- 未满 2 秒在触发带松手，取消并保留原收藏位置及原浏览器标签页；满 2 秒只改变反馈，不提前建块、移动链接或关闭标签页。只有在已触发的落点松手才提交一次。
- 新块在指示位置创建，固定初始名称为“新收藏”，允许同名，直接展开且不弹出重命名。用户仍可通过既有编辑功能稍后更名。
- 待选来源生成独立收藏链接，备注为空且不弹表单；重复网址继续允许。已有链接来源执行移动，保留其身份、标题、图标、备注、待办标记及既有待办顺序，原块变空仍保留。同空间移动及跨空间限制继续适用。
- 建块与新增或移动链接作为一次完整的本地保存操作；不先保存空块再单独放入链接。失败时不留下新空块、不丢失或移动原链接、不关闭原浏览器标签页；重复的拖放处理不能产生多次建块。
- 普通已有块接收与快捷建块均遵循先成功保存到本地、再尝试关闭原标签页的顺序；不等待云端同步。同步失败保留本地收藏，继续沿用现有同步错误与重试机制。
- 只对被拖动的那个浏览器标签页执行关闭，其他同网址标签页保留，置顶标签页同样适用。保存失败保留原页并提示；关闭失败保留已保存收藏并提示，不因关闭失败回滚或重复收集。
- 原标签页在拖动期间已关闭时，使用拖动开始时的信息完成收藏，不将原页缺失作为关闭错误。原标签页已经跳转到其他网址时，保存拖动开始时的信息，保留跳转后的页面并提示原页已变化。
- 完全没有收藏块的空间不提供快捷建块落点，空状态不接收网页或链接；用户先通过已有按钮创建至少一个收藏块。普通空白松手始终取消。
- 待选区域继续仅展示当前窗口可收藏的 HTTP/HTTPS 网页，不新增跨窗口汇总。增强条目底色与背景的区分，保留现有浅色、低饱和视觉及可读的标题、图标和交互状态。
- UI 优先使用 UnoCSS 工具类；复用外观采用现有 tailwind-variants 方式，沿用共享控件。运行时拖动位置、尺寸和动画可沿用既有测量方式，不借此重做样式体系或视觉背景。
- 沿用本地优先与 ADR 0002 的夸克独立版本同步，WebDAV 继续作为兼容与迁移入口。新收藏块及顺序参与已有数据保存和同步，不另建同步系统或持久化计时状态。

## Testing Decisions

- 沿用先前已确认的最高测试边界：在隔离 Chrome 配置中运行真实新标签页扩展，通过完整用户流程验证界面、浏览器标签页、本地持久化及受控同步服务。继续使用现有 Playwright 工作台验收及受控 HTTPS 网页、夸克/WebDAV 服务，不新增生产组件接口或另一套主要测试边界。
- 好的测试断言可见反馈、落点顺序、收藏内容、浏览器标签页是否关闭，以及重开后的保存结果。避免锁定组件树、内部函数、类名、Query 键、计时字段或实现用的动作名称；视觉检查可测量可见几何位置，不绑定特定样式工具类。
- 既有待选拖入、预览及占位、空块/折叠块接收、卡片/收藏块/空间排序、Todo 独立顺序、键盘拖动、窄窗口抽屉、离线保存和跨客户端同步是复用先例。替换旧测试中“原标签页保留”“悬停仍保留待选条目高度”和“待选始终追加到末尾”的旧期待。
- 通过真实拖动验证进入整个中间收藏内容区域即显示卡片预览；在中间空白处可见卡片预览但松手不提交。在已有收藏块的开头、中间和末尾分别验证占位与最终顺序一致，并覆盖多列卡片、空块和折叠块。
- 通过真实拖动覆盖两个块之间、第一块上方与最后一块下方的建块位置，验证 24px 触发带不覆盖卡片，且相邻两块共享间隙只表示一个目标。
- 检查进入时的淡线、未满 2 秒不发光且松手取消、满 2 秒出现发光及提示、继续按住不提交、松手只创建一个块。计时断言以 2 秒前后可观察行为为准，给渲染调度保留合理等待，不要求逐帧像素一致。
- 覆盖同一间隙内移动、切换间隙、离开重进、取消、触发后离开和中间内容滚动，确保可提交状态与当前落点一致，不沿用先前位置的计时。
- 分别以待选网页和已有链接快捷建块，验证插入位置、固定名称、直接展开、无命名弹窗及同名允许；已有链接保留属性与待办顺序，原空块保留，重开后新块与顺序仍在。
- 构造同网址多个标签页、置顶标签页、原页已关闭和拖动期间跳转，验证只关闭准确的原标签页；原页变化时收藏保存拖动快照，并保留新页面及显示提示。
- 使用隔离扩展与受控故障方式分别构造本地保存失败、浏览器关闭失败及云端同步失败，断言收藏、原块、原页和错误反馈的最终结果。核心成功与失败流程仍从真实拖拽进入，不通过直接调用内部新增动作代替验收。仅为故障场景使用必要控制，不增加面向日常用户的测试入口。
- 验证普通空白、完全没有收藏块的空间、Todo 和搜索不会误收集、误建块或误关闭原页；整个收藏块、空间和 Todo 行继续按原用途排序，内部控件及点击打开网页不受拖动干扰。
- 覆盖鼠标、触摸和键盘输入，以及桌面、窄窗口待选抽屉。保存实际 Chrome 中的可见反馈截图，结合实时交互判断待选底色、卡片预览、占位及发光线，不用单张截图证明 2 秒交互正确。
- 验证本地离线收集、页面及浏览器重开、恢复联网后的同步，并在第二个客户端检查新块、链接及顺序。复用既有备份与同步回归，确认浏览器临时标签页身份不进入收藏业务数据。
- 功能交付时执行项目 TypeScript 类型检查、Chrome 生产构建及相关真实扩展验收；根据改动运行已有持久化、同步和 Todo 顺序回归。

## Out of Scope

- 完全没有收藏块时通过空状态拖入创建第一个块，或在任意中间空白处松手自动建块。
- 在 Todo 或搜索弹窗中新增收藏、移动收藏或快捷建块，以及改变整个收藏块拖动的排序用途。
- 手动填写新增链接、点击批量收藏、批量拖选或一次拖入多个网页。
- 跨空间收藏链接移动、跨窗口标签页汇总、网址去重或强制收藏块名称唯一。
- 新增重命名弹窗、主题或动效设置、深色视觉方向，或重做流体背景及样式体系。
- 重构同步与账号体系、调整云端历史或回收站期限、引入持久化浏览器标签页关联或新同步格式。
- 新浏览器专项适配、扩展商店发布，以及未约定的全设备性能目标。

- 本规格依据 2026-11-12 的四项需求及 Q1～Q7 回答整理。用户随后调用 to-spec，授权将已讨论内容综合成规格并发布为带 ready-for-agent 标签的 GitHub Issue，无需再次访谈。
- 这是已有收藏工作台及 Issue #2 的后续增量。本规格替代旧规格中的“收藏后保留原标签页”和“待选预览保持原尺寸直到松手”的约定；其他功能继续以既有规格及 ADR 为依据。
- 用户明确否决空空间专用拖入建块落点：必须先有至少一个收藏块。该限制同时适用于视觉提示、落点识别及最终提交。

- 具体底色、圆角、发光强度及卡片过渡参数由实施时选择，接受可读性、现有浅色风格、明确落点及已约定 24px/2 秒行为约束，不新增用户配置。
