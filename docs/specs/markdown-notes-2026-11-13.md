## Problem Statement

用户希望在整理网页收藏的同一处快速记录内容，但目前收藏块只能保存收藏链接，不能直接新建并持续编辑笔记。阅读浏览器中的本地或在线 Markdown 文件时，也缺少统一的排版阅读、标题大纲和本地文件目录体验；本地编辑还需要可靠写回原文件，避免因权限、离线或并发修改丢失内容。

## Solution

在收藏块增加新建笔记图标按钮，点击后立即创建标题为「新笔记」、正文为空的扩展托管笔记，并在新的浏览器标签页打开独立的文档页面。页面使用 Milkdown 提供类似 Notion 的排版编辑和只读阅读，顶部编辑笔记标题，左侧默认显示文档大纲；自动保存本地，随收藏同步和备份，也能导出 Markdown。

同一文档页面支持本地 Markdown 文件和在线 Markdown 文件。Chrome／Edge 在用户授权后支持本地原文件写回和惰性文件目录；Firefox 支持本地文件阅读、编辑后下载另存。在线文件仅支持阅读。收藏入口、页面打开文件／文件夹，以及默认开启的 Markdown 地址自动接管共同进入此页面。

## User Stories

1. 作为整理收藏的用户，我希望在收藏块点击新建笔记图标后立即获得一篇空笔记，从而不必选择磁盘位置就能开始记录。
2. 作为新建笔记的用户，我希望初始标题为「新笔记」且自动打开新的浏览器标签页，从而立即进入编辑。
3. 作为查看收藏块的用户，我希望笔记卡片与链接卡片尺寸和基本样式协调，并以固定文件图标和不同背景区分，从而快速识别内容类型。
4. 作为查看笔记卡片的用户，我希望看到笔记名称和自动提取的描述，从而不打开正文也能判断内容。
5. 作为编辑笔记的用户，我希望描述来自第一个有效文本块的纯文本，从而不必维护第二份摘要。
6. 作为查看空笔记的用户，我希望无有效正文时描述留空、长描述仅在卡片显示时截断，从而保持卡片整洁。
7. 作为管理笔记的用户，我希望卡片操作只有删除，从而避免出现不适用的待办按钮或链接编辑弹窗。
8. 作为组织收藏的用户，我希望笔记和链接可以混排并拖动排序，从而按自己的阅读顺序整理内容。
9. 作为组织收藏的用户，我希望将笔记移动到其他收藏块，从而随内容变化调整归属。
10. 作为查找内容的用户，我希望全局搜索同时匹配笔记标题和正文，从而找回记录过的信息。
11. 作为编辑笔记的用户，我希望文档页面独立于收藏管理界面、只保留文档相关功能，从而专注书写。
12. 作为使用多个页面的用户，我希望文档页面沿用应用的背景和主内容视觉风格，从而获得一致体验。
13. 作为编辑托管笔记的用户，我希望顶部标题独立于正文编辑，从而修改名称时不自动插入或改写正文标题。
14. 作为编辑 Markdown 的用户，我希望直接在排版后的正文中书写，从而获得类似 Notion 的编辑体验。
15. 作为阅读笔记的用户，我希望可以切换只读阅读模式，从而避免阅读时误改内容。
16. 作为书写文档的用户，我希望支持常用 Markdown、表格、任务列表、代码高亮和图片链接，从而完成常见记录任务。
17. 作为阅读长文的用户，我希望左侧默认展示正文各级标题形成的大纲，从而掌握文章结构。
18. 作为阅读长文的用户，我希望点击大纲条目跳转到对应正文位置，从而快速定位内容。
19. 作为使用托管笔记或在线文件的用户，我希望文件目录切换按钮禁用，从而明确当前来源不提供本地目录浏览。
20. 作为持续书写的用户，我希望修改及时自动保存本地，从而不必手动点击保存。
21. 作为离线用户，我希望托管笔记可继续编辑并在重开后保留，从而网络中断不影响记录。
22. 作为多设备用户，我希望托管笔记的标题和完整正文随收藏同步夸克，从而在另一设备继续阅读和编辑。
23. 作为备份用户，我希望现有备份导出、导入和恢复包含完整笔记，从而迁移收藏时不丢失正文。
24. 作为需要独立文件的用户，我希望将托管笔记导出为以标题命名的 .md 文件，且内容为正文，从而在其他应用使用。
25. 作为书写中的用户，我希望平时只看到轻量保存状态，从而自动保存不会打断输入。
26. 作为遇到本地保存失败的用户，我希望看到明确提示且未保存内容保留并可重试或导出，从而避免误以为数据已保存。
27. 作为网络不稳定的用户，我希望云同步失败不影响本地编辑和已保存内容，从而稍后可以继续同步。
28. 作为打开同一笔记多个标签页的用户，我希望后打开的页面先只读，从而减少同时编辑造成的覆盖。
29. 作为希望切换编辑位置的用户，我希望点击「在此编辑」接管编辑权、原页面随即只读，从而明确当前可写页面。
30. 作为跨设备修改同一正文的用户，我希望冲突时保留两个版本供选择，从而不因同步静默丢失任一侧内容。
31. 作为单独删除笔记的用户，我希望立即从当前收藏数据永久删除该笔记且不进入回收站，从而按约定清除当前条目。
32. 作为删除整个收藏块或空间的用户，我希望其中笔记随父级进入回收站并可随父级恢复，从而仍能恢复整组内容。
33. 作为仍打开被删除笔记的用户，我希望编辑页立即停止接受修改并显示删除状态，从而自动保存不会让已删除内容重新出现。
34. 作为理解删除边界的用户，我希望明确当前数据永久删除不会追溯清除已有云端历史快照或我导出的备份，从而对保留范围有准确预期。
35. 作为打开本地 Markdown 地址的用户，我希望先进入排版预览，从而在未授予写权限时也能阅读。
36. 作为希望修改本地文件的 Chrome／Edge 用户，我希望通过「编辑原文件」选择文件并授权写回，从而将后续编辑自动保存到原文件。
37. 作为直接打开本地文件的用户，我希望文档页面提供打开本地文件和文件夹的入口，从而不必先创建收藏链接。
38. 作为选择本地文件夹的 Chrome／Edge 用户，我希望一次文件夹授权后能浏览并编辑其中的 Markdown 文件，从而连续处理相关文档。
39. 作为查看本地目录的用户，我希望仅显示 Markdown 文件和子目录并隐藏其他文件，从而目录聚焦当前阅读任务。
40. 作为打开大型文件夹的用户，我希望只有展开子目录时才读取其内容，从而避免主动扫描整个目录树。
41. 作为只授权单个文件的用户，我希望切换文件目录时获得清晰的文件夹授权引导，从而知道为何还需要额外选择。
42. 作为本地权限失效的用户，我希望当前编辑内容保留并获得重新授权入口，从而恢复写回时不丢失输入。
43. 作为遇到磁盘外部修改的用户，我希望保留磁盘版本和编辑版本供选择，从而不会直接覆盖其他程序的修改。
44. 作为 Firefox 用户，我希望能够阅读本地 Markdown、编辑后下载另存，并看到目录能力不可用的说明，从而仍有可用的文档处理路径。
45. 作为查看外部文件的用户，我希望顶部显示文件名且不提供重命名，从而明确页面不会因修改显示标题而改动磁盘文件名；本地正文标题仍可编辑。
46. 作为打开在线 Markdown 的用户，我希望进入只读排版阅读，从而查看远端内容而不误以为可写回服务器。
47. 作为点击收藏中 Markdown 链接的用户，我希望使用统一文档页面打开，从而无需另装阅读工具。
48. 作为直接导航 Markdown 地址的用户，我希望默认自动接管 .md 或 .markdown 主页面地址，兼容大小写、查询参数和锚点，从而自然进入阅读页面。
49. 作为希望保留浏览器原行为的用户，我希望在设置中关闭自动接管，从而自行决定 Markdown 地址的打开方式。
50. 作为浏览普通网页的用户，我希望接管仅作用于主页面导航，从而不影响页面中的 iframe、资源请求和链接内容。
51. 作为遇到后缀为 Markdown 但实际返回 HTML 的用户，我希望收到「此地址不是 Markdown」提示并能打开原网页，从而继续访问原内容。
52. 作为遇到在线加载失败的用户，我希望可以重试或打开原网页，且回退不会形成接管循环，从而能自行恢复阅读。
53. 作为阅读在线文件的用户，我希望相对图片和链接按原始来源地址解析，从而保持文档资源关系。
54. 作为阅读本地文件的用户，我希望相对资源按已授权文件夹解析，权限不足时获得授权提示，从而加载本地图片和关联文档。
55. 作为点击关联 Markdown 文档的用户，我希望继续使用文档页面阅读或编辑，从而保持连续浏览体验。
56. 作为管理收藏的用户，我希望外部文件不会因被打开而自动复制成托管笔记，且内部文档页保持被待选区域排除，从而维持现有收藏边界。

## Implementation Decisions

- 托管笔记是归属于收藏块的独立内容类型，包含稳定标识、独立标题、Markdown 正文、混排位置以及现有同步和删除机制所需的信息。不得把正文塞入收藏链接的备注字段，也不得将笔记伪装成可编辑网址的链接。
- 扩展收藏领域模型、层级校验、操作协议及持久化，使创建、编辑、混排排序、跨收藏块移动、搜索、回收站、备份、导入和远端合并完整识别笔记；沿用现有空间与收藏块边界，待办仍只属于收藏链接。
- 笔记创建先本地持久化成功，再打开对应独立文档标签页；创建失败时保留可重试状态并明确提示，避免展示已创建但实际未保存的笔记。
- 文档来源统一区分托管笔记、本地文件和在线文件。页面根据来源和已授权能力决定是否可编辑、是否可写回和是否可进入文件目录，外部来源不自动复制为托管笔记。
- 新增独立文档页面入口，复用应用背景与主内容视觉，不带入空间管理、待办、待选区域等收藏管理功能。托管笔记顶部标题可编辑，外部文件顶部文件名只读，正文区域统一使用 Milkdown；编辑和阅读模式共享文档语义。
- 样式遵守现有 UI 约定：优先 UnoCSS 工具类，重复组合使用 tailwind-variants/lite，复用共享按钮和图标接口；Milkdown 的第三方 DOM 与主题适配遵循项目允许的样式例外。
- 文档大纲从正文标题生成并支持定位。卡片描述从首个有效文本块提取纯文本，跳过空行、纯图片、分隔线、代码块及文件头元数据；标题和列表文字可作为描述，没有有效文字时留空，只在卡片呈现时截断。
- 遵循 ADR 0003「托管笔记随收藏快照保存」：正文与标题属于现有本地工作副本，沿用按数据源／账号隔离的收藏快照、夸克同步和完整备份。电脑或夸克中不额外维护每篇笔记的独立 Markdown 文件，单篇文件通过导出获得。
- 自动保存区分及时本地持久化与合并连续修改后的云端上传，避免每次按键产生完整云快照。沿用 ADR 0002 的不可变版本、祖先引用与冲突保留原则；离线和云端失败继续保留本地修改。
- 编辑页显示轻量保存状态；本地保存失败或权限失效必须明确提示，保留未保存内容并允许重试、重新授权或导出，不提前显示保存成功。
- 托管笔记的编辑权以数据源和笔记标识共同限定；同一浏览器只允许一个编辑页，其他页只读，主动接管后原页停止标题和正文写入。保存、编辑权交接和删除应协调处理，避免迟到写入覆盖新内容或复活已删除笔记。
- 跨设备正文冲突使用版本选择；本地文件写回前检测磁盘外部修改，遇到变化保留两侧内容供选择。正文协同编辑不在此范围内。
- 遵循 ADR 0004「单篇笔记删除绕过回收站」：单篇删除直接永久清除当前业务数据中的正文并保留同步所需删除信息；父级删除时笔记随父级进入回收站。已打开页面立即停止写入；父级恢复后可继续编辑，单篇永久删除没有回收站恢复入口。
- 永久删除不追溯清理既有云端历史快照与用户导出的备份，继续遵循 ADR 0002；旧设备同步不应静默复活已删除笔记，已有显式冲突处理仍需避免丢失双方内容。
- Chrome／Edge 的本地文件访问分为文件网址访问、文件写回授权和目录授权。接管本地地址先预览，用户点击「编辑原文件」选择文件并授权写回；目录模式需选择所在文件夹。通过文件夹入口授权后，可浏览和编辑其中的 Markdown；不能把单文件授权当成父目录授权。
- 文件目录仅枚举当前目录的 Markdown 文件和子目录，展开子目录才枚举其内容；隐藏非 Markdown 文件。权限失效时保留内容，重新授权后恢复相关能力。Firefox 采用阅读、编辑后下载另存和目录禁用说明的降级路径。
- 导航接管默认开启且可关闭，识别 HTTP(S) 与本地文件主页面 URL 路径的 .md、.markdown 后缀，忽略大小写，保留查询参数、锚点与原始来源信息；没有扩展名的接口不自动识别。不改写普通页面链接，不接管 iframe 或资源请求。
- 扩展入口、后台导航与浏览器声明需要按目标浏览器接入相应接管机制及必要权限；权限未启用时提供可操作说明。回退「打开原网页」必须绕过该次接管，避免错误循环，内部文档页面继续符合现有待选区域排除规则。
- 符合后缀规则但返回 HTML 的地址提示不是 Markdown，提供原网页入口，不做站点展示页转换。网络或读取失败提供重试和原网页入口，在线文件始终只读。
- 在线相对资源按原始来源地址解析，本地资源按已授权文件夹解析；权限不足提示授权。关联 Markdown 继续进入文档页面，编辑能力由目标来源和权限决定。
- 托管笔记导出以标题生成合法的 .md 文件名，导出内容为正文，独立标题不自动插入正文。本地文件页面不提供重命名。
- 数据格式扩展必须能读取现有不含笔记的数据与备份；不兼容或损坏数据继续显式报错并保留原数据，不能因新类型造成已有收藏被清空。保留现有 WebDAV 连接与迁移入口的兼容性，不改变其领域数据归属。
- 现有云快照与备份有体积约束，新增正文不能静默截断或丢失；超过当前可保存边界时要保留本地内容并提示失败，不在本规格中另造附件存储架构。

## Testing Decisions

- 用户已确认测试边界：以现有 Playwright 真实扩展入口作为主要验证入口，覆盖创建、编辑、重开、同步和文件导航的用户流程；复用现有夸克测试服务，不为编辑器内部、卡片或大纲分别增加测试接口。
- 好的测试断言用户可见行为和最终持久化结果：正文是否保留、另一设备是否可读取、目录是否可用、文件是否正确写回、失败时是否能恢复。避免锁定 UnoCSS 类名、Milkdown 内部节点结构、组件实现、具体防抖时长或内部方法调用次数。
- 复用现有扩展工作台测试的持久化浏览器配置、多标签页、多设备隔离、受控本地 HTTPS 服务、离线／上传失败、下载与备份导入设施；夸克协议通过既有隔离测试服务验证，不依赖真实账号或生产网络。
- 既有先例包括「夸克扫码后签名上传并轮换 Cookie，重开和另一设备读取收藏」「离线编辑重开保留，不同条目合并；同条目冲突保留两份并选择」「父级删除与离线编辑冲突」「特殊页面和本地文件一键收藏、重载并通过浏览器接口重新打开」，以及已有回收站彻底删除和旧设备同步不复活的行为测试。
- 端到端覆盖新建即持久化并打开新标签页、标题和正文自动保存、卡片摘要更新、重开与离线恢复、全文搜索、混排排序和跨块移动；同时验证笔记无待办／链接编辑操作，其他收藏功能保持可用。
- 端到端覆盖排版编辑与阅读切换、在线只读、大纲层级和跳转、支持的 Markdown 语法、文件名只读、正文导出和完整备份往返；核对导出文件正文不被独立标题改写。
- 多页面／多设备测试覆盖后开只读、主动接管编辑权、旧页停止写入、云正文冲突保留两侧、单篇永久删除、父级删除恢复、删除时迟到保存及同步后不静默复活。
- 受控页面服务覆盖 .md／.markdown、大写后缀、查询参数、锚点、开关关闭、HTML 响应、网络失败、重试、原网页绕过接管、相对资源、关联文档跳转；证明 iframe 与资源请求不被接管。
- 仅在浏览器文件选择与授权这一外部边界提供可控替身，以确定性验证拒绝／撤销授权、写入失败、磁盘外部修改及目录枚举。使用临时文件／目录和实际文件内容验证保存结果，证明展开前不枚举子目录；不以纯内存编辑成功代替文件写回验证。
- 用 Chrome／Edge 真实浏览器补验系统文件选择、文件网址访问、写回和目录授权；用 Firefox 验证实际阅读、编辑后下载另存、目录禁用说明和对应导航行为。浏览器差异必须明确记录，Chrome 的通过不能代替另外两个浏览器的验收。
- 对无法在浏览器流程充分验证的永久删除与同步标记等领域规则，可按现有回收站领域测试先例增加少量行为测试；不为解析、UI 子组件或实现细节另开大量独立入口。
- 验证桌面和窄窗口下文档主体、大纲／目录、核心操作、禁用状态与键盘焦点可用；完成类型检查和 Chrome、Edge、Firefox 对应构建。测试重点为已改动行为与具体回归风险。

## Out of Scope

- 在夸克或电脑中为托管笔记自动创建并持续维护独立 .md 文件。
- 在线文件写回、在线文件编辑、站点 HTML 展示页转换及没有 Markdown 后缀接口的自动识别。
- 本地文件或在线文件因打开而自动导入托管笔记，以及本地文件重命名。
- 图片文件上传、剪贴板图片托管、附件存储、数学公式和 Mermaid。
- Markdown 源码编辑模式、源码与预览分栏、实时多人协作或正文自动协同合并。
- 子目录展开前主动递归扫描整个文件树，以及为非本地来源提供文件目录。
- 笔记待办标记、链接编辑弹窗，以及把收藏管理功能整体搬入文档页面。
- Firefox 的原文件自动写回与完整目录浏览，以及绕过系统文件授权。
- 追溯清理用户备份、清除云端历史快照正文或重做云快照保留机制。

## Further Notes

- 本规格来自 2026-11-13 已完成的设计访谈；用户已逐项接受产品选择，并明确授权按已确认测试方案发布 Issue。当前任务产物为可供实现的规格，不包含功能实现或已通过功能测试的声明。
- 术语沿用领域词汇中的空间、收藏块、收藏链接、笔记、笔记卡片、文档大纲和文件目录；「笔记」专指扩展托管内容，不与本地 Markdown 文件或收藏链接备注混用。
- ADR 0002 继续决定收藏快照和历史保留；ADR 0003 明确笔记存储归属；ADR 0004 明确单篇与父级删除的差异。早期特殊页面规格中「只同步本地文件网址和元信息，不复制文件」继续适用于外部本地文件。
- 此前探查发现现有单云快照上限为 10MB，备份导入界面上限为 15MB，且旧客户端不识别新增实体类型。实现时须验证并清晰处理新旧数据边界；这些数值描述当前约束，并非为笔记新增的产品额度。
- Milkdown 使用用户指定的官方入门文档作为集成依据，具体依赖版本及浏览器权限声明在实现时按实际兼容性确认；文件句柄和授权不能由普通 file URL 静默获得。
