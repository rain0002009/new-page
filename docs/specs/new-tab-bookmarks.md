# Chrome 新标签页收藏、全局 Todo 与 WebDAV 同步

## Problem Statement

用户在浏览过程中会积累大量打开的网页，需要把值得保留的页面快速整理到不同空间和收藏块中，并从收藏中挑出需要继续处理的内容。普通书签与打开的标签页相互分离，逐项填写表单或点击保存会打断收集过程；只保存在当前设备又无法在多台电脑之间延续整理结果。

本项目目前仅有 Extension.js 的 React、TypeScript 新标签页欢迎页，没有收藏管理、待选区域、Todo、搜索、持久化或同步能力，也没有自动化测试。

## Solution

将 Chrome 新标签页变成柔和亮色的三栏收藏工作台：左侧切换空间与功能，中间按收藏块展示链接卡片，右侧实时展示当前窗口可收藏的网页。用户将待选网页拖入收藏块即可收藏，也可以通过右上角批量收藏图标，为当前窗口的网页创建一个命名收藏块。

每张收藏卡片有独立的书签开关，点亮即进入全局 Todo，完成即熄灭并从 Todo 移除。所有内容改动自动保存本地，再通过用户配置的 HTTPS WebDAV 后台同步；断网时仍然可以继续编辑。

## User Stories

1. 作为首次使用者，我希望没有本地数据时看到配置入口，以便连接自己的 WebDAV 数据源。
2. 作为首次使用者，我希望填写昵称、HTTPS WebDAV 地址、用户名和密码或应用专用密码，以便开始保存和同步收藏。
3. 作为首次使用者，我希望连接失败时看到可理解的原因，以便修正地址、权限或凭据。
4. 作为已有远端数据的用户，我希望连接后读取原有收藏，以便继续使用而不被新建的空数据覆盖。
5. 作为新建数据的用户，我希望获得一个“我的空间”和一个空收藏块，以便立即开始收集网页。
6. 作为用户，我希望每次打开新标签页先看到已有本地数据，以便无需等待网络请求。
7. 作为用户，我希望后台刷新远端数据，以便看到其他设备上的修改。
8. 作为用户，我希望看到明亮但不刺眼的奶白、浅灰和鼠尾草绿界面，以便长时间使用。
9. 作为用户，我希望左侧显示昵称、空间和 Todo、搜索、设置入口，以便快速切换工作内容。
10. 作为用户，我希望默认显示第一个空间，以便每次打开时获得确定的起点。
11. 作为用户，我希望进入 Todo、搜索或设置时保留左右两栏，以便维持导航和当前标签页的上下文。
12. 作为窄窗口用户，我希望右侧待选区域收起为可打开的抽屉，以便中间内容仍然可用。
13. 作为用户，我希望卡片采用适中密度并随宽度调整网格，以便同时阅读标题、备注和足够多的收藏。
14. 作为用户，我希望创建空间，以便区分不同主题的收藏。
15. 作为用户，我希望重命名空间，以便表达当前主题。
16. 作为用户，我希望拖拽排序空间，以便调整导航顺序和默认空间。
17. 作为用户，我希望删除空间前看到受影响内容数量并确认，以便避免误删。
18. 作为用户，我希望始终至少保留一个空间，以便收藏始终有可用的顶层位置。
19. 作为用户，我希望在空间内创建命名收藏块，以便进一步整理链接。
20. 作为用户，我希望重命名收藏块，以便随内容变化调整分组含义。
21. 作为用户，我希望拖拽排序收藏块，以便按自己的阅读和使用顺序组织内容。
22. 作为用户，我希望折叠和展开收藏块，以便减少不相关内容对页面的占用。
23. 作为用户，我希望删除不需要的收藏块并能恢复，以便安全地调整分组。
24. 作为用户，我希望链接卡片显示网站图标、标题和备注，以便快速识别内容。
25. 作为用户，我希望图标缺失时仍能看到清晰的占位图标，以便页面保持可读。
26. 作为用户，我希望悬浮卡片时出现编辑、删除与待办书签操作，以便按需管理链接。
27. 作为用户，我希望点击链接卡片在新标签页打开网页，以便保留当前收藏工作台。
28. 作为用户，我希望在收藏块中手动添加链接，以便收藏不在当前窗口里的网页。
29. 作为用户，我希望通过编辑弹窗修改网址、标题和备注，以便纠正或补充收藏信息。
30. 作为用户，我希望编辑后的有效改动自动保存，以便无需点击单独的保存按钮。
31. 作为用户，我希望拖拽卡片调整块内顺序，以便按自己的使用习惯排列链接。
32. 作为用户，我希望把卡片拖入同空间的另一个收藏块，以便重新分类。
33. 作为用户，我希望拖拽时不能跨空间移动收藏链接，以便保持空间边界。
34. 作为用户，我希望折叠的收藏块也能接收拖入并在添加后展开，以便不必先手动展开目标。
35. 作为用户，我希望相同网址可以多次收藏，包括放在同一收藏块中，以便按不同用途独立维护。
36. 作为用户，我希望重复网址的收藏拥有各自的标题、备注和待办状态，以便一条收藏的修改不影响另一条。
37. 作为用户，我希望右侧只显示本新标签页所属窗口的普通网页，以便收集当前工作上下文。
38. 作为用户，我希望每个待选条目带有标题、网址和图标，以便识别网页并直接拖入。
39. 作为用户，我希望打开、关闭、更新、排序或跨窗口移动标签页后待选列表随之更新，以便列表反映实际窗口。
40. 作为用户，我希望把待选网页拖入收藏块后立即创建收藏链接，以便一次操作完成收藏。
41. 作为用户，我希望拖入时直接使用已有标题、网址和图标，备注初始为空，以便无需填写或确认弹窗。
42. 作为用户，我希望收藏后原标签页继续保留，以便不中断正在浏览的内容。
43. 作为用户，我希望待选区域只收集 HTTP/HTTPS 页面，以便排除浏览器设置页、扩展页和新标签页等特殊页面。
44. 作为用户，我希望右上角保留批量收藏图标，以便一次整理当前窗口的全部可收藏网页。
45. 作为用户，我希望批量收藏弹窗只要求填写新收藏块名称，以便快速在当前选中空间中创建收藏块。
46. 作为用户，我希望批量收藏也允许重复网址并保留原标签页，以便得到当前窗口内容的独立收藏。
47. 作为用户，我希望每张收藏卡片的书签图标独立点亮或熄灭，以便表达是否需要处理。
48. 作为用户，我希望全局 Todo 展示所有空间中书签点亮的收藏链接，以便集中处理。
49. 作为用户，我希望在 Todo 中点击完成后卡片立即消失、原收藏的书签熄灭，以便完成处理且保留收藏。
50. 作为用户，我希望需要再次处理时回到原收藏卡片点亮书签，以便重新加入 Todo。
51. 作为用户，我希望 Todo 只包含当前待处理的收藏链接，以便不需要维护独立任务或已完成列表。
52. 作为用户，我希望搜索全部空间的标题、网址和备注，以便找到记忆不完整的收藏。
53. 作为用户，我希望搜索结果标明所在空间与收藏块，以便理解收藏位置。
54. 作为用户，我希望从搜索结果执行链接操作或定位到原收藏块，以便快速打开和整理内容。
55. 作为用户，我希望单个链接、收藏块和空间删除后进入回收站并保留 30 天，以便撤销误删。
56. 作为用户，我希望删除父级时子内容一起进入回收站，以便不会留下不可见的孤立收藏。
57. 作为用户，我希望已删除链接从 Todo 消失，以便待办只显示有效收藏。
58. 作为用户，我希望恢复收藏时还原原有待办标记，以便恢复误删前的工作状态。
59. 作为用户，我希望断网或认证失效时仍可新增、编辑、删除和整理内容，以便继续工作。
60. 作为用户，我希望未上传修改立即持久化并在重开页面或浏览器后保留，以便不丢失操作。
61. 作为用户，我希望恢复连接后自动同步待上传修改，以便无需重复提交。
62. 作为用户，我希望本地修改不会被后台拉取的旧数据覆盖，以便保留离线工作。
63. 作为多设备用户，我希望不同收藏条目的并行修改自动合并，以便减少人工处理。
64. 作为多设备用户，我希望同一内容发生冲突时保留两个版本并让我选择，以便不会静默丢失任一修改。
65. 作为用户，我希望看到同步中、待同步、失败与冲突等状态并可手动同步，以便知道数据是否已到远端。
66. 作为用户，我希望昵称、空间、收藏块、收藏链接、待办标记和回收站同步到 WebDAV，以便跨设备延续工作。
67. 作为用户，我希望 WebDAV 密码只保留在当前设备且不进入导出备份，以便控制访问凭据的传播范围。
68. 作为用户，我希望在设置中修改昵称和 WebDAV 配置，以便调整显示名称和连接信息。
69. 作为用户，我希望导入、导出备份，以便备份或迁移收藏数据。
70. 作为用户，我希望切换 WebDAV 时选择切换到另一份数据或迁移当前数据，以便明确操作目的。
71. 作为用户，我希望切换数据源时隔离本地缓存与待上传内容，以便不会把一个账号的数据误传给另一个。
72. 作为用户，我希望迁移时先读取目标数据，目标非空时确认合并，以便避免直接覆盖已有收藏。
73. 作为用户，我希望浏览器权限被拒绝或 WebDAV 服务能力不足时获得明确提示，以便修复连接而不损失本地数据。

## Implementation Decisions

- 延续现有 Extension.js Chrome 新标签页扩展，使用 React、TypeScript 和 pnpm；引入 UnoCSS 与 tailwind-variants 管理样式和组件变体。首版交付目标是 Chrome。
- 领域层次为“空间 → 收藏块 → 收藏链接”。每个收藏条目需要稳定且独立的身份，不能把网址当作唯一标识；顺序、所属关系和待办标记都属于条目状态。
- 以应用层操作统一执行收藏、编辑、拖拽排序、跨块移动、删除、恢复和待办切换。由该边界维护同空间移动、至少一个空间、父子关系和数据源隔离等约束，避免界面与后台分别定义规则。
- 新标签页界面由空间导航、中间功能页和待选区域组成。默认进入第一个空间；其他功能页保留两侧区域，批量收藏使用当前选中空间作为目标。
- 浏览器标签页适配负责查询本页面所属窗口与监听标签页生命周期、顺序及跨窗口变化。收藏动作复制网页元信息，不关闭或移动原标签页；特殊页面不进入可收藏集合，缺失元信息采取可读的降级展示。
- 待选条目拖入有效目标时直接创建收藏链接，无弹窗、无补充表单。批量收藏图标保留，并只通过命名弹窗创建新收藏块；自动保存与该快捷操作同时存在。
- 卡片悬浮时展示操作；待办书签点亮状态在卡片上可识别。编辑弹窗自动保存有效修改，无单独保存按钮；编辑输入无效时不破坏已保存的有效数据。输入提交和防抖等细节属于实现选择，不能改变拖入即收藏的行为。
- 待办标记为每条收藏链接独立的布尔状态。Todo 是跨空间筛选视图，不建立独立任务副本、第三种“已完成”状态或完成历史。完成等价于熄灭标记，再次加入在收藏处操作。
- 搜索只涵盖有效收藏，匹配标题、网址、备注并显示空间与收藏块归属；结果可操作和定位原位置。
- 回收站保留删除内容的身份、父子关系和待办标记；父级删除使子内容同时离开有效收藏和 Todo。恢复应保持有效的层次关系；原父级仍在回收站时，不将子链接暴露为孤立条目。30 天后清理与删除事实的同步必须协调，避免旧设备把已删除内容重新带回。
- 延续已记录的本地优先 WebDAV 同步架构：本地持久层保存工作副本与未上传修改，远端适配层读写 WebDAV 应用数据，同步层协调拉取、合并和上传。浏览器重启、页面关闭或扩展后台重启不应丢失已完成的本地修改。
- TanStack Query 是适合读取、后台刷新和请求状态的候选库，可在实现阶段采用；它的查询缓存不能成为用户内容或未上传修改的唯一持久化来源，缓存失效也不能删除业务数据。本规格不将缓存库选择当作多设备冲突处理方案。
- WebDAV 使用用户配置的 HTTPS 服务，不绑定特定提供商。首次连接验证认证、读取和必要写入能力，目录布局与数据编码属于实现选择；远端数据需要版本信息和可迁移的格式，读取失败或格式不兼容时不覆盖原数据。
- WebDAV 网络访问置于获授权的扩展后台边界。标签页访问与用户选定服务器的访问权限按功能申请；拒绝或撤销权限时显示可恢复状态，不影响已有本地数据。
- 同步先合并本地未上传修改与已读取的远端版本，再安全写入；应利用服务端实际可验证的条件写入或等效并发控制。遇到不支持所需安全写入能力的服务，明确报错并保留本地待上传数据，不降级为不受保护的整文件覆盖。
- 不同条目修改自动合并，同一内容的冲突保留两份并呈现选择入口；重试和重复刷新不得重复应用同一修改。删除、排序与恢复也属于同步内容，不能只合并卡片文本。
- 昵称、空间、收藏块、链接、顺序、待办与回收站属于同步数据。WebDAV 凭据留在当前设备，不写入远端业务数据、日志或导出备份；不会把本地存储描述为天然加密。
- 缓存、未上传修改与同步进度必须按数据源和账号隔离。切换数据源不自动向新源上传旧源数据；迁移当前数据时先读取目标，目标非空必须确认合并。
- 备份导出包含可恢复的业务数据及格式版本，不包含密码。导入先验证格式并保留有效数据，不因失败而清空当前收藏。
- 当前只有模板组件和后台日志，没有现成的业务接口或测试先例；实施时新增一个面向完整用户工作流的主要测试边界，避免为每个组件、Hook 或内部实现创建独立的测试接口。

## Testing Decisions

- 用户已确认测试边界：从新标签页执行真实用户操作，验证可见界面、重开后的本地数据，以及连接测试 WebDAV 后的同步结果。优先通过这一最高层边界覆盖功能；不针对每个组件和 Hook 镜像实现编写测试。
- 测试只断言外部行为和持久化结果，不断言内部函数调用次数、组件树、CSS 类名、Query 键或内部数据结构。相同的用户操作应允许内部重构。
- 浏览器流程覆盖空间、收藏块、链接卡片、Todo、搜索、设置、回收站、待选区域与真实扩展后台的连接。拖拽用浏览器输入事件操作，验证落点、位置、元信息和页面重开后的结果，不能仅调用内部移动函数代替拖拽验收。
- 采用隔离的浏览器用户配置、可控网页标题与图标、受控 HTTPS WebDAV 测试端点和独立数据目录，避免依赖用户的真实账号、密码或线上收藏。具体测试框架在实现阶段选定。
- 首次连接分别覆盖空远端、已有远端数据、错误凭据、权限拒绝和不支持必要能力的服务；只有空远端初始化默认内容，不能因读取错误而把已有远端当作空数据。
- 核心收藏验收覆盖：待选拖入立即生成匹配标题、网址和图标的卡片、无弹窗、备注为空、原标签页保留；块内排序、同空间跨块、拒绝跨空间、空块和折叠块接收拖入；重复网址形成独立条目；缺失图标可读；特殊页面被排除。
- 批量收藏验收覆盖：图标弹窗只要求名称，在当前选中空间创建一个块并包含全部可收藏网页，重复网页不被去重，特殊页面不进入收藏，原标签页不关闭。空的可收藏集合应有清晰空状态，不误报已收藏。
- 编辑与自动保存验收覆盖：修改有效字段、关闭弹窗并重开页面，内容仍在；无效网址不破坏已有数据；新增、删除、排序与待办操作也无需单独保存。内容变更时页面快速关闭也不丢失已确认的修改。
- Todo 验收覆盖：点亮后进入全局列表，完成后移出且原收藏保留并熄灭，回到收藏可再次点亮；两个同网址条目的状态互不影响；无手动任务与已完成列表。
- 搜索验收覆盖全部空间的标题、网址与备注，结果显示归属且可定位和编辑；删除内容不参与有效收藏搜索。
- 回收站验收覆盖单个链接、收藏块与空间的删除和恢复，空间删除确认与最后一个空间保护，子内容完整恢复，待办恢复及 30 天到期行为；时间通过受控时钟推进，无需实际等待。
- 本地优先验收覆盖远端延迟期间先显示缓存，离线编辑后页面和浏览器重开仍保留，再联网后自动上传，以及认证失效时继续编辑后恢复同步。
- 两个隔离客户端连接同一个测试数据源，分别覆盖不同条目的修改合并、同一内容的冲突提示与保留、并发删除和编辑、并行排序与移动、重复重试及远端条件写入失败；验收不发生静默覆盖、重复新增、孤立条目或删除内容复活。
- 数据源切换验收覆盖缓存和待上传操作隔离；迁移到非空目标必须确认合并；导出无密码、合法备份可恢复、错误备份不损坏当前数据。
- 以窄窗口与桌面宽度检查三栏、抽屉、长标题、备注、加载、空状态与错误提示，并验证键盘可触发主要操作，图标按钮有可辨识名称。
- 项目当前无测试框架和类似自动化用例。已有的 Chrome 生产构建与 TypeScript 类型检查继续作为交付检查；它们不能替代上述行为验收。外部 WebDAV 服务兼容性只宣称经实际验证的范围。

## Out of Scope

- 夸克网盘二维码登录、非公开接口逆向、CLI 或本地辅助程序接入。
- 自建账号体系、第三方账号登录、多人共享或协作编辑。
- 普通手动 Todo、独立任务实体、已完成历史、提醒、截止日期和周期任务。
- 收藏链接跨空间拖拽移动。
- 重复网址限制、自动去重和整理功能。
- 浏览器设置页、扩展页、新标签页等特殊网址的收藏，以及全浏览器多窗口汇总。
- 收藏后自动关闭原标签页，以及浏览器标签组和会话完整恢复。
- 暗色主题、主题编辑器、网页全文抓取和正文搜索。
- HTTP WebDAV、自定义服务商专属协议，以及未经验证就保证兼容所有 WebDAV 服务。
- WebDAV 密码跨设备同步、进入导出备份或端到端加密同步方案。
- Firefox、Edge 等浏览器专项适配，扩展商店上架与发布流程。
