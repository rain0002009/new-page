# 夸克只保留当前文件，使用本地基线合并

2026-11-14 用户反馈一次同步约 4.10 秒，并明确不需要导致云端文件堆积和整批下载的同步历史。本决定取代 ADR 0002 和 ADR 0005 的历史提交与版本向量：以「页墟收藏/收藏.json」作为唯一当前远端数据，保留独立 Markdown、回收站和手动导出，本机已有的同步基线用于三方合并。

普通同步只读取当前 JSON，不列举笔记目录、不下载 Markdown。新建笔记接口保留，创建笔记、编辑页保存、导入迁移、删除恢复等明确操作只为受影响笔记登记本机待发布 ID；未完成操作在离线、关闭编辑页或重启后可补传，同步期间的后续编辑不会被本轮确认清除。Markdown 是派生副本，不从网盘反向合并或全库自动修复。

JSON 仍先上传临时文件、下载校验、检查当前文件版本，然后更名发布并删除旧副本。Markdown 只对待发布笔记列举目录一次，根据内容摘要和文件元数据跳过已发布版本；使用已有上传完成协议，不下载旧正文或上传后回读，也不再上传后重列目录。MD 遗留临时文件按稳定笔记 ID 识别，重试重新上传而不信任文件名声明的内容。写入前已检查主目录时复用结果，不为笔记再重复检查；提交 JSON 前和发布后确认当前文件的查询保留。有效发布当前文件后清理旧同步历史，失败下次重试，不读取历史目录内容。

当前 JSON 只增加一个递增同步版本号，阻止已确认的新数据因目录延迟被旧内容回退；这不是历史归档，也不提供原子写入保证。更名中断后优先按上次文件标识恢复已校验的旧当前文件；首次发布可恢复内容摘要匹配的完整临时文件，候选不唯一时停止自动恢复。对象键顺序变化不构成数据变化，不会触发额外上传。

夸克没有已验证的服务端条件写入接口；写入前检查和重名更名失败只能检测部分并发，不能保证严格的并发隔离。保留通常的跨设备交替同步与冲突选择，接受最后检查到提交之间的竞争窗口；不再提供云端历史恢复或不可变分支保留。若当前文件丢失或损坏则停止同步，保留本地数据，不根据旧历史静默重建。

设置提供显式“修复夸克同步”：确认后查找原目录或唯一的「页墟收藏」目录，缺失时创建目录，并持久保存新的目录绑定。仅本次修复允许用本地数据补建缺失的当前文件，并为全部笔记检查、补建 Markdown；已有完整当前文件仍按正常三方合并处理，损坏、多个同名目录、登录或网络异常仍停止。普通同步继续遵守缺失文件保护；修复失败可重试，本地来源标识与文档编辑权保留。
